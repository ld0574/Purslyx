本文将需求说明中的资料隔离、历史可追溯、删除、使用次数和成本口径转成可生成、可评审的数据库规则。技术选型固定为 PostgreSQL 18、SQLAlchemy 2、psycopg 3 和 Alembic；发布时锁定具体 18.x 镜像版本及摘要。仓库尚无服务端模型或迁移文件。下文的“必须”表示**本草案获评审采纳后的实现要求**，不表示当前代码已经满足。内部主键、无外键策略、字段精度及模块文档模板是本规范的待评审设计，不冒充已实现的事实。

## 1. 设计原则与数据边界

1. **PostgreSQL 是业务事实来源**：资料版本、任务状态、使用次数、预算、模型尝试、反馈和检查点关联以数据库记录为准；Redis/Celery 消息与缓存不决定是否交付或扣减。
2. **账号归属可验证**：每条可由用户读取的业务数据必须有明确的 `account_id` 和引用链；查询、写入、下载及 Worker 发布结果时均校验目标存在、账号归属和删除状态。
3. **输入和结果可追溯**：确认资料、JD、期望、评分规则、提示词与产物按版本关联；运行中的任务只读提交时冻结的版本，不读取“最新版本”。
4. **结算与成本分开**：功能使用次数按可交付业务结果结算一次；每次真实模型调用及失败、修复、重试分别记成本，未知用量或费用保留为 `NULL`。
5. **删除先阻断访问，再清理正文**：用户确认删除后立即使相关资料及衍生结果不可读，同时取消未完成任务；私有文件、正文副本与检查点按清理流程移除，保留不含正文的必要使用次数与成本流水。
6. **结构化事实用列与约束表达**：归属、状态、余额、金额、版本引用、幂等键和检索字段不得只放在 JSONB 中。JSONB 用于已验证的可变结构结果或受限编辑内容。
7. **无外键下主动维护完整性**：数据库负责主键、唯一、`CHECK` 与事务原子性；Service/Worker 负责跨表引用校验和删除编排，每日只读巡检发现孤儿与跨账号引用。ORM 关系不等于数据库完整性约束。

本规范只覆盖首版已有需求的数据边界，包括求职者私有匹配池、去投递点击事件、后台角色与权限、使用次数发放和站点概况；不预建支付订单、公开人才市场、企业团队权限、批量筛选、自动投递或平台投递回执监控等后续功能表。

## 2. 命名与组织

- 表、列、索引、约束、迁移标识统一小写 `snake_case`；表名使用英文复数，如 `accounts`、`document_versions`、`ai_tasks`、`model_call_attempts`。避免 `tbl_`、`data`、`info` 等无语义名称。
- 单数实体引用用 `_id`，如 `account_id`、`document_version_id`；时间点用 `_at`；计数用 `_count`；外部可见随机标识用 `public_id`；布尔事实用 `is_`。业务状态用 `status` 或有业务含义的后缀，如 `verification_status`。
- 用户输入原文与规范化值分开命名，如 `salary_text`、`salary_min`、`salary_currency`；模型推断、用户确认、浏览器采集应有来源字段，不混称 `value`。
- 约束和索引命名：`pk_{table}`、`uq_{table}_{columns}`、`ck_{table}_{meaning}`、`idx_{table}_{columns}`。名称超过 PostgreSQL 63 字节上限时使用明确缩写，并在模块文档中列出全称映射。
- 模块命名遵循[首版模块与页面清单](../01-product/首版模块与页面清单.md)：服务端按用户、简历、匹配池、面试、任务、用量和统计组织；岗位采集属于匹配池的浏览器侧能力；去投递跳转由 Web 与服务端记录。数据库对象按实体命名，不把所有模块数据合并进通用 `records` 表。

## 3. 标识、归属与引用

### 3.1 内部主键与接口标识

默认业务表使用 `id BIGINT GENERATED ALWAYS AS IDENTITY` 作内部主键。对外可在路径或响应中出现的资源另设不可预测的 `public_id UUID NOT NULL DEFAULT gen_random_uuid()`，加唯一约束；API 不暴露自增 `id`。随机标识只降低枚举风险，不能替代账号归属检查。纯内部流水、关联表和检查点映射可不设 `public_id`；多对多纯关联表优先使用联合主键。

### 3.2 账号归属

用户资料、简历、分析、匹配池岗位、去投递跳转事件、面试、任务、使用次数、模型调用、反馈与私有文件元数据显式保存 `account_id BIGINT NOT NULL`，并建立查询索引；纯全局配置表可例外。`account_id` 与其他 `_id` 字段都是逻辑引用，不自动生成外键。写入父子关系时，Service/Worker 必须在同一事务中读取父对象，校验其存在、账号一致、注册身份与资源用途正确，并排除已删除或因祖先删除而失效的对象。不能信任客户端提交的 `account_id`。跨资源查询也必须同时限定本账号和有效状态。

`accounts` 中求职／招聘注册身份使用受约束的非空列，首版创建后不可由客户端或管理端修改；同一规范化邮箱只对应一个账号，另一身份须用另一邮箱另注册。各账号资料和使用次数独立，招聘方记录的候选人资料归招聘账号所有，候选人期望须保留其明确提供的来源，不读取其他账号的默认求职期望。后台角色与权限独立于注册身份，不改变业务资料归属。

后台授权至少由 `admin_roles`、`admin_permissions`、`admin_role_permissions`、`account_admin_roles` 和 `admin_audit_events` 表达。权限键由代码与种子明确列出，首版至少含查看用户、管理角色、发放次数、查看统计；超级管理员可在管理端调整角色的权限组合及账号角色，但不能修改注册身份。两个关联表的双侧引用都建索引及唯一约束，写入时锁定并校验目标账号、角色和权限仍有效。受控命令建立首位超级管理员；内置超级管理员角色不可编辑，操作者不能修改自己的角色或移除最后一位超级管理员。角色和授权变更与含操作者、目标、动作、前后值、理由及时间的审计事件同事务提交。审计记录不包含简历或 JD 正文。

### 3.3 无外键引用与巡检

业务表默认不建数据库 `FOREIGN KEY`，不使用数据库级联删除。所有 `_id` 引用字段必须在模块索引清单中登记并有可覆盖实际查验/关联查询的显式索引；复合索引可覆盖多个引用，但须注明查询条件，不机械重复建单列索引。联合主键若只覆盖关联表的一侧引用，另一侧另建索引。父对象校验与子记录写入置于同一事务，更新或删除父对象的流程使用相同的行锁顺序；涉及删除竞态时读取父行使用 `SELECT ... FOR UPDATE`。物理删除元数据前须完成依赖清理或保留可解析的最小审计关联。确需外键的例外由模块设计写明理由并经专项评审。

上线后每天至少执行一次只读引用巡检，覆盖 `account_id` 指向的账号、资料/版本/任务/使用次数及后台角色授权等内部引用及 LangGraph 检查点映射，报告不存在的目标、跨账号关系和已删除父对象仍可见的子对象。巡检记录表、引用列、异常数量和样本 ID，并发出告警；不得自动删改或把异常当作正常业务数据。修复另走经审核的数据迁移，完成后复查。该巡检不能替代写入时的事务校验。

## 4. 公共字段、时间与并发

普通可修改且可被用户删除的业务表默认包含：

```sql
id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
account_id  BIGINT NOT NULL,
created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
deleted_at  TIMESTAMPTZ NULL
```

`accounts` 不需要 `account_id`；不可变版本、模型尝试、使用次数事件、去投递跳转事件、后台操作日志与队列出站记录按各自生命周期保留 `created_at`，不为“统一”而加入无意义的 `updated_at` 或 `deleted_at`。`updated_at` 在实际更新时由 ORM 或显式 SQL 写入；数据库默认值只覆盖插入，不能保证后续自动更新。并发编辑的资料、岗位版简历与期望设置应有 `revision BIGINT NOT NULL DEFAULT 1` 或等价版本号，使用条件更新，冲突返回 409。

所有时间点使用 `TIMESTAMPTZ`；应用写入带时区时间，数据库会话统一 UTC，展示时再转为用户时区。`created_at`、`deleted_at`、租约和令牌过期时间都用时间点。业务自然日可使用 `DATE`，如全站预算按 `Asia/Shanghai` 自然日记录 `budget_date`；在写入时从同一时间点和明确时区计算，不能依赖数据库会话默认时区。每个字段的 `COMMENT` 应写明是时间点还是业务日期。

## 5. 数据类型与空值语义

| 用途 | 建议类型与规则 |
| --- | --- |
| 内部标识、次数 | `BIGINT`；计数 `NOT NULL` 且 `CHECK (x >= 0)` |
| 状态和封闭枚举 | `SMALLINT NOT NULL`，逐字段定义代码映射、`CHECK` 和默认值；接口可转换为语义字符串 |
| 金额及薪资 | `NUMERIC`，禁止 `FLOAT`/`REAL`/`DOUBLE PRECISION`；薪资建议 `NUMERIC(14,2)`，美元成本建议 `NUMERIC(20,8)`，保留币种与计量周期 |
| 比例与分数 | 量表计算使用 `NUMERIC` 或明确精度的应用十进制运算；持久化未舍入值和规则版本，显示时才舍入 |
| 邮箱 | 保存规范化检索值并对有效账号建唯一索引；长度以实际邮件服务约束确定，不以 `TEXT` 无限放开 |
| 密码摘要、令牌摘要 | 足够容纳当前算法输出的 `VARCHAR` 或 `TEXT`；只存摘要，不存明文令牌 |
| 来源 URL、路径 | `TEXT`；做格式、长度、来源及私有路径校验，不把服务器绝对路径暴露给客户端 |
| 结构化内容 | `JSONB`，写入前用版本化 Schema/Pydantic 校验；只索引确有查询需求的路径 |

未知值用 `NULL` 并结合状态字段表达，不把未知写成零、空串、“不限”或“面议”。特别是薪资条件应分别记录原文、数值区间、币种、周期、税制、发薪月数、值状态及约束强度；只有同口径且信息足够时才做代码比较。`salary_min <= salary_max` 等同表规则写成 `CHECK`，允许任一端未知；绝不擅自补猜 12 薪、税率或汇率。默认求职期望与一次分析使用的期望快照分开保存。

## 6. 状态、版本与来源

每个业务状态独立定义允许值，禁止照搬其他项目“0=禁用、1=正常”的全局含义。封闭业务状态在数据库中使用 `SMALLINT`，代码用 `IntEnum`，接口转换为稳定的语义名称。任务状态至少覆盖架构约定的 `queued`、`running`、`retry_wait`、`needs_input`、`succeeded`、`failed`、`cancelled`；数据库值、API 名称、`CHECK` 和迁移中的映射必须逐项一致。面试“等待回答”属于会话状态，不让任务长期占用运行租约。状态转换在服务层集中实现，关键流转有事务条件更新。

用户确认后的资料、JD、期望快照、简历成品输入及分析依据视为不可变版本：修改生成新版本，不覆盖旧版。可编辑的“当前草稿”另设可变记录和 `revision`。版本需要 `account_id`、父资源 ID、版本号、创建时间、来源类型及内容/结构版本；同一父资源的版本号唯一。分析、改写、面试和导出记录显式保存实际使用的版本 ID，不能只存“当前版本”指针。

模型提取草稿与用户确认内容分开。证据至少可定位到资料版本、稳定段落 ID、引用文字和来源类型；保存前校验段落存在且引用文字与确认内容一致。用户补充事实另存来源、确认时间和所属账号，不回写原始文件或原始简历。规则、量表、提示词、模型及模板版本随结果保存，保证历史结果能解释；结果中的得分、覆盖率和条件状态不得只凭再次运行模型重建。

## 7. 删除、清理与保留

可由用户删除的资料、私有匹配池岗位、报告、简历和面试等资源使用 `deleted_at` 表示**立即不可访问**。所有面向用户的读取默认过滤已删除父对象和其受影响后代；Repository/查询构造器集中实现，文件下载、异步任务和管理统计也检查。不能仅给顶层行打标而让旧 `public_id`、文件 URL、跳转事件关联或检查点继续可读。

删除流程在一个事务中记录删除事件、锁定并标记影响范围、取消相关未完成任务；提交后异步清理原文件、成品 PDF、提取正文、模型正文缓存及 LangGraph 检查点。清理任务可重试，失败应记录并告警；物理清理时限本轮不作承诺，不能让清理失败恢复产品访问。Worker 在写入结果或结算前复查来源是否删除及执行代次，迟到结果不得复活内容。首版只定义资料与历史删除，账号注销另行设计；历史备份恢复仍须遵循技术架构的离线核验与删除记录重放要求。

使用次数发放、预留、结算、释放、模型调用与必要的无正文审计记录采用追加式流水，不因删除资料而重置余额。流水只保存资源 ID、事件类型、时间、数量和成本元数据，不嵌入简历、JD、回答或邮件正文；具体保留期限、用户隐私告知与备份过期策略在上线前确定。会话、验证令牌、临时导入草稿按过期时间清理，不统一软删除。

## 8. 约束与索引

- 每张表有主键；业务唯一性在数据库中表达。可重用的名称或邮箱若只对有效记录唯一，使用 `WHERE deleted_at IS NULL` 的部分唯一索引；不可重用的任务幂等键与结算键使用不带软删除条件的永久唯一约束。
- 核心唯一键包括：账号规范化邮箱、同父资源版本号、`(account_id, action, idempotency_key)`、同任务最终成功结算、同预留编号的释放/结算事件、同一面试会话的轮次 ID、同账号同试用批次发放记录、同账号同一次去投递点击令牌、后台角色名、权限键、角色权限对、账号角色对、后台次数发放幂等键与授权操作幂等键。名称及具体列以模块设计文档为准。
- 每个 `_id` 引用字段均须对应明确的索引，并列出所服务的账号限定、父子查询或巡检查询；已有复合索引可覆盖时在清单中指明。其他索引从实际查询确定：账号与创建时间的列表、待发布任务的状态和计划时间、租约超时、待清理记录、任务尝试、预算日期、使用次数账号/类型、证据所属版本、私有匹配池列表以及去投递跳转事件的去重与日期查询，以及后台角色授权、发放和操作日志按目标及时间查询。软删除业务列表可用 `WHERE deleted_at IS NULL` 部分索引；审计流水与不可变历史不要机械套用部分索引。
- 复合索引遵循等值过滤、范围/排序的实际查询形态。低区分度 `status` 不单独建全表索引；大表或 JSONB 检索先用 `EXPLAIN (ANALYZE, BUFFERS)` 与测试数据验证。索引数量没有任意硬上限，但新增索引须列出服务的查询和写入成本。
- `CHECK` 用于同表、确定性约束，如非负使用次数、薪资上下界、合法状态、租约时间顺序；跨表归属由事务内校验和每日巡检守护，余额与任务结算一致性由唯一约束、行锁及事务共同保证。

示例：`account_id` 是逻辑引用，须显式索引；账号存在性与归属由 Service/Worker 在事务内校验。具体字段仍需模块设计确认。

```sql
CREATE TABLE documents (
    id            BIGINT GENERATED ALWAYS AS IDENTITY,
    public_id     UUID NOT NULL DEFAULT gen_random_uuid(),
    account_id    BIGINT NOT NULL,
    document_type SMALLINT NOT NULL,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    deleted_at    TIMESTAMPTZ,
    CONSTRAINT pk_documents PRIMARY KEY (id),
    CONSTRAINT uq_documents_public_id UNIQUE (public_id),
    CONSTRAINT ck_documents_document_type CHECK (document_type IN (1, 2))
);

CREATE INDEX idx_documents_account_id_created_at
    ON documents (account_id, created_at DESC)
    WHERE deleted_at IS NULL;

COMMENT ON TABLE documents IS '账号拥有的原始资料元数据；正文与私有文件另存';
COMMENT ON COLUMN documents.id IS '内部主键，不对外返回';
COMMENT ON COLUMN documents.public_id IS '对外使用的随机资源标识';
COMMENT ON COLUMN documents.account_id IS '所属账号 ID，应用层校验引用，不建外键';
COMMENT ON COLUMN documents.document_type IS '资料类型示例：1=简历，2=岗位 JD；正式枚举以模块设计为准';
COMMENT ON COLUMN documents.created_at IS '创建时间点';
COMMENT ON COLUMN documents.updated_at IS '最后更新时间点';
COMMENT ON COLUMN documents.deleted_at IS '删除时间点；非空时立即禁止访问';
```

示例中的枚举只演示约束写法，不预先确定所有资料类型。字段、表及约束都必须有可读注释；枚举注释列出全部取值，敏感字段注释说明摘要、加密或来源。迁移与 ORM 注释保持一致。

## 9. 任务、幂等、队列发布与去投递点击

`ai_tasks` 保存账号、注册身份、功能、请求摘要、幂等键、冻结输入版本、业务状态、执行代次、租约、结果引用与时间；待发布的 Celery 消息单独写 `task_outbox`。创建任务、预留功能使用次数与写队列出站记录在**同一数据库事务**完成。发布队列成功后标记已发布；Redis 重启或 Worker 未认领时按数据库记录补发。消息只传任务标识，正文从已授权的版本读取。队列出站记录不是用户点击“去投递”的事件，二者不得共用表或统计口径。

请求按 `(account_id, action, idempotency_key)` 唯一，同键同请求摘要返回原任务，同键不同摘要拒绝；主动生成新版本使用新键。Worker 认领时用事务条件更新状态、租约与 `execution_generation`；步骤产物、检查点关联和最终结算只接受当前代次。外部模型调用前写尝试记录，调用返回后保存用量和产物；若结果是否已由供应商执行不明，状态为待核实，不把超时解释为零成本。

`model_call_attempts` 一次外部调用一行，记录任务、步骤、尝试序号、供应商/模型、价格版本、开始/结束时间、已知 token 用量、估算成本、状态与重试来源。输入、缓存、输出和推理 token 分列；推理 token 属于输出用量子集，不重复相加。正文与凭据不写进尝试流水。需要恢复的步骤产物单独存放并绑定任务代次；LangGraph `thread_id` 与账号、业务会话/任务及清理状态建立明确映射。

私有匹配池条目属于求职账号，引用已确认 JD 版本、当前采用的简历与期望版本，以及逐条分析任务／报告；资料不足或使用次数不可用时记录待分析原因。用户同意一次分析消耗且前提齐全时，岗位入池、使用次数预留、分析任务和队列出站记录在同一事务提交，重试不重复创建条目或结算。岗位来源网址与正文按私有资料处理，不构建公开岗位库。

去投递点击使用独立的不可变事件记录，保存求职账号、私有匹配池条目、平台、已保存的原 JD 链接引用、一次性点击令牌及服务端记录点击的时间。服务端在同一事务校验账号、岗位归属、未删除状态、HTTPS 与 BOSS／猎聘域名白名单，写入事件并以 `(account_id, click_token)` 永久唯一去重；只有写入成功才发出 303 跳转。同一令牌重试复用原目标，不新增计数。服务端无法核验浏览器是否收到跳转响应、外部页面最终加载或是否提交申请，因此统计只能称“去投递点击数”，按 Asia/Shanghai 的服务端记录点击日期汇总。链接无效或记录失败时不发起跳转且不计数；不存平台成功回执、回复状态或浏览器页面观察证据。用户删除岗位后旧入口立即不可读；无正文的必要计数流水可按保留规则留存。

## 10. 功能使用次数与全站预算

求职账号适用分析、改写、面试三类使用次数，招聘账号只适用分析次数；不同账号不共享。试用发放按 `(account_id, grant_batch)` 唯一并核对固定注册身份。余额表可用于加速读取，但使用次数流水是可审计依据；余额变更与预留/结算/释放事件必须同事务提交。每次预留有独立编号，余额检查在行锁或条件原子更新下完成，确保 `granted - settled - reserved >= 0`。

管理端“发放次数”只接受目标注册身份适用的功能、正数数量、必填原因及幂等键。授权校验后锁定目标账号与该功能的余额记录，追加发放流水、更新余额并写操作日志，同一事务提交；`(operator_account_id, idempotency_key)` 对该动作唯一，同键同请求返回原结果、同键不同内容拒绝。不能直接覆盖余额、借发放变更注册身份或给招聘账号发放改写／面试次数。发放记录保留目标、功能、数量、原因、操作者、时间及变更前后值，供用户与授权管理人员复核。

分析/改写只在完整结果已持久化且可读取时结算一次；面试只在开场问题成功保存时结算一场，后续回答与恢复不重复扣减。失败或 `needs_input` 释放当前预留；同任务重试可以有新的预留，但最终成功结算按 `(account_id, feature, business_task_id)` 唯一。重试调用的成本仍逐次累计。免费操作不生成虚假的功能使用次数扣减。

全站美元预算按 `Asia/Shanghai` 日期建立预算桶，并在每次模型调用前原子预留成本上界及并发名额。已知实际成本按价格版本结算并释放差额；未知用量/费用保留 `NULL` 和保守预算占用，待复核后更正，不能默认为 0。跨日未核实占用继续影响新日可用预算，实际调用统计归属原开始日。所有成本字段记录币种；价格表保留生效版本与核验来源。每日 30 美元是技术架构中已确定的初始全站控制值，不写死在数据库 `CHECK` 或迁移里。

## 11. 隐私、文件与权限

密码存 Argon2id 摘要；会话标识及邮件验证/重置令牌只存不可逆摘要、到期时间和使用/撤销时间。邮箱用于检索时保存规范化值并控制读取权限；账号原文、候选人资料、私有岗位正文及产品反馈原文不能流入通用日志或模型成本台账。敏感字段不进入异常堆栈、任务消息、JSONB 扩展字段或统计聚合结果。

数据库保存私有文件的逻辑键、所属账号、类型、大小、摘要、内容版本和清理状态；原始文件与 PDF 放服务器私有目录，访问必须经服务端鉴权。文件摘要只在同账号内用于复用，不能跨账号公开相同文件存在与否。数据库记录和文件创建/删除跨系统时使用可重试状态机，避免“有元数据无文件”被当成成功。备份覆盖 PostgreSQL、检查点、文件和版本清单并加密；恢复前核对删除记录、使用次数与预算流水，恢复环境先保持离线。

后台权限、固定注册身份、资源归属和软删除过滤同样适用于 API、Worker、文件下载及统计查询。站点概况以聚合和去标识数据为主；独立后台权限不意味着可以浏览候选人或私有岗位正文。任何客户端传入的 `account_id`、角色、资源 ID、`thread_id` 均不可直接信任。

## 12. ORM 与事务实现

ORM 统一使用 SQLAlchemy 2 与 psycopg 3。模型使用类型标注和 `mapped_column`，`DateTime(timezone=True)` 映射时间点，`Numeric`/Python `Decimal` 映射金额，`JSONB` 配版本化 Schema。无数据库外键时，`relationship()` 必须显式配置 `primaryjoin`，用 `foreign()` 标记引用侧；账号资源之间的关联条件须同时限定 `account_id`。关系只用于导航，不能当作写入完整性校验。`created_at` 与 `updated_at` 设数据库默认值；更新时显式维护 `updated_at`，对批量 SQL 和 Worker 更新也生效。不可变版本和流水禁止普通更新，确需更正时增加更正事件或新版本。

Repository 层提供统一的账号范围、软删除过滤与版本读取接口。Service/Worker 在同一事务中锁定并校验所引用的父行，完成跨表归属检查、状态流转、使用次数原子更新和 outbox 写入；数据库对未经过这些入口的写入不提供引用完整性保护，因此维护脚本和迁移也必须使用相同的校验规则。不要在 ORM 回调里暗中调用模型或发布 Celery 消息。读取列表和下载均明确处理父资源已删除的情况。事务中的外部文件或模型调用必须移到事务外，使用持久状态及重试补偿。

## 13. 迁移、种子与发布

统一使用 Alembic 管理 PostgreSQL 18 结构变更，禁止手工更改生产表。流程为：修改模型和模块数据设计 → `alembic revision --autogenerate` → 人工审查 DDL、引用索引、`CHECK`、注释、默认值与回填，并确认未意外生成外键 → 在脱敏样例库演练 → Review → 备份后发布。自动生成结果不能视为完整设计。开发、测试和部署环境使用 PostgreSQL 18；发布镜像锁定具体 18.x 版本及摘要，并先验证目标 ARM 环境。

- 迁移使用单一路径、语义化文件名，记录依赖顺序；DDL 与大量数据回填分开。对现存大表采用加可空列、回填、校验、加约束的阶段式变更。
- 修改状态编码或量表版本时提供旧数据解释与兼容窗口；历史结果不得因新规则被无声改写。
- 破坏性变更写明回退或前向修复方案，并先评估备份、检查点、文件元数据和旧任务的兼容性。并非所有数据删除都能靠 `downgrade()` 恢复。
- 种子只放确定的配置或测试数据；内测使用次数批次、管理账号和价格版本通过受控配置/维护命令初始化，不在迁移中写入真实个人信息或凭据。
- 每次发布记录迁移版本、备份标识与恢复演练结果。当前仓库没有迁移目录，这些是未来实现的验收规则。

## 14. 模块数据库设计文档模板

新增业务模块在 `docs/02-technical/` 放一份 `{模块名}数据库设计.md`，与服务端模块对应；文件名使用清单中的短名，例如 `用户数据库设计.md`、`匹配池数据库设计.md`。浏览器侧脚本没有独立数据库模块，其岗位与去投递事件由匹配池、统计模块设计承接。文档标题下用两列表格 `项 | 内容`，固定列出模块、版本、更新日期、状态、范围、依赖模块和需求/架构依据。主体章节的标题与顺序固定如下；不适用时保留标题并写“无”及原因，不得跳章或调序：

```text
## 1. 设计目标与边界
## 2. 实体关系
## 3. 表结构
## 4. 索引清单
## 5. 检查约束清单
## 6. 枚举与版本字典
## 7. 事务与生命周期
## 8. 关键设计决策
## 9. 待讨论项
```

第 1 章逐项注明需求编号或技术约束。第 2 章统一使用 Mermaid `flowchart LR`，每条边标明基数、逻辑引用列和账号归属；默认无外键，不把逻辑引用画成数据库约束。第 3 章每表一个三级标题，完整列出公共字段，字段表固定六列、顺序不变：

| 字段名 | 数据类型 | 可空 | 默认值 | 约束/索引 | 说明 |
| --- | --- | --- | --- | --- | --- |
| account_id | BIGINT | 否 | — | Index | 所属账号 ID；应用层校验逻辑引用 |

字段名用小写 `snake_case`，类型含长度/精度，可空只填“是/否”，无默认值填 `—`。约束/索引列使用 `PK`、`UK`、`Index`、`CK: 表达式` 等标记；逻辑引用填 `Index`，说明列写“引用 xxx.id，应用层校验”。枚举列全值，敏感字段注明处理方式，JSONB 注明 Schema 版本。基础字段不可用“见通用规范”省略。

第 4 章索引表固定为 `表名 | 索引名 | 字段或表达式 | 类型 | 条件与用途`，包括主键、唯一、每个 `_id` 逻辑引用的覆盖索引和部分索引条件；写明对应查询或每日巡检。第 5 章固定为 `表名 | 约束名 | 表达式 | 说明`，只列数据库真正执行的 `CHECK`，跨表规则写在第 7 章。第 6 章枚举表固定为 `表.字段 | 数据库值 | API 名称 | 含义 | 备注`，并另列量表、Schema、提示词及模板版本的保存位置和兼容规则。第 7 章固定为 `操作/触发 | 事务内校验与写入 | 事务外动作/补偿 | 幂等与失败结果`，覆盖创建、版本变更、删除、任务恢复和结算等适用流程。第 8 章记录真实取舍和代价；第 9 章只列尚未决策且影响本轮实现的问题，不把未来功能凑成待办。

一个模块一份文档，不按每张表拆文件。字段注释、设计文档、ORM 模型和迁移要相互一致；AI 生成代码前按固定表头与章节校验，生成后逐项对照实际迁移。用户故事未要求的未来能力不要为“可扩展”预先建表。

## 15. 评审与验收检查

每个新增或修改的模块设计至少检查以下问题：

| 主题 | 必须能回答 |
| --- | --- |
| 归属 | 记录如何回到账号？每个逻辑引用是否有索引，写入时是否在同一事务校验存在、归属与删除状态？ |
| 版本 | 用户修改后旧任务、旧报告和证据指向哪个确认版本？ |
| 删除 | 删除确认后哪些入口立即失效，文件/正文/检查点怎样重试清理？ |
| 使用次数 | 并发请求、重复幂等键、失败重试和面试续答是否只产生一次合法结算？后台追加次数是否核验身份适用功能、留原因和流水且不覆盖余额？ |
| 后台权限 | 注册身份是否固定？角色与权限是否独立、受控授权且有审计？是否阻止自改角色与移除最后一位超级管理员？ |
| 成本 | 免费导入、失败及修复尝试是否入账？未知费用是否保持未知和预算占用？ |
| 查询 | 列表、任务补投、租约、预算和历史读取的索引是否对应真实查询？ |
| 巡检 | 每日只读巡检能否发现孤儿、跨账号引用和已删除父对象仍可访问的子对象，并告警而不自动修复？ |
| 发布 | 迁移、回填、备份、旧任务兼容和恢复路径是否经过样例演练？ |

本文件获评审采纳后，任何例外须写在相应模块数据设计的“关键设计决策”中，并说明对归属、历史、删除、使用次数与成本的影响；不能只以“实现方便”绕过这些业务不变量。
