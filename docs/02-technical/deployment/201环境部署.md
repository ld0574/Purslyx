# 201 环境部署约定

本项目演示环境固定使用【本地开发环境.md】中的 201 PostgreSQL，不提供 SQLite fallback。

## 连接方式

201 环境直接开放 PostgreSQL 服务，应用通过环境变量 `DATABASE_URL` 连接
【本地开发环境.md】记录的 `purslyx` 数据库和账号：

```text
DATABASE_URL=postgresql+psycopg://purslyx@10.10.10.201:5432/purslyx
PGPASSWORD=<本地开发环境文件中的 PostgreSQL 密码>
```

真实密码只从被 `.gitignore` 忽略的本地开发文件或进程环境变量读取，不提交到 Git。
不要把连接串复制进源码、日志或前端。

## 启动前检查

```bash
scripts/start_201_local.sh
```

脚本默认监听 `127.0.0.1:8001`，如 8000 端口空闲可显式设置
`PURSLYX_PORT=8000`。它会读取被 Git 忽略的《本地开发环境.md》并将密码只注入
进程环境；不会接受其他数据库地址，也不会把真实密码拼进 URL、源码、命令记录或前端。

应用启动时会拒绝缺失的 `DATABASE_URL`、SQLite URL、其他非 PostgreSQL URL 以及非 201 主机；启动后
`GET /health` 会返回数据库后端类型，便于演示时现场确认连接的是 201 PostgreSQL。
`PURSLYX_DEBUG` 和 `PURSLYX_AUTO_VERIFY_LOCAL` 只用于本地演示，正式部署应接入邮件验证并
关闭这两个开关。

## 最小演示范围

明天的 SDD 演示只走一条纵向链路：提交简历文字和 JD → 确认资料版本 → 生成可复核匹配报告。
邮件、浏览器授权、Celery 和后台管理不作为本次启动前置条件，避免把演示变成全量平台交付。
