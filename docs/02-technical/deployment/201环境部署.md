# 201 环境部署约定

本项目本地开发环境固定使用【本地开发环境.md】中的 201 PostgreSQL，不提供 SQLite fallback。

## 连接方式

201 环境直接开放 PostgreSQL 服务，应用通过环境变量 `DATABASE_URL` 连接
【本地开发环境.md】记录的 `purslyx` 数据库和账号：

```text
DATABASE_URL=postgresql+psycopg://purslyx@10.10.10.201:5432/purslyx
PGPASSWORD=<本地开发环境文件中的 PostgreSQL 密码>
```

真实密码只从被 `.gitignore` 忽略的本地开发文件或进程环境变量读取，不提交到 Git。
不要把连接串复制进源码、日志或前端。

## 启动前检查

```bash
scripts/start_201_local.sh
```

脚本默认监听 `127.0.0.1:8001`，如 8000 端口空闲可显式设置
`PURSLYX_PORT=8000`。它会读取被 Git 忽略的《本地开发环境.md》并将密码只注入
进程环境；不会接受其他数据库地址，也不会把真实密码拼进 URL、源码、命令记录或前端。

应用启动时会拒绝缺失的 `DATABASE_URL`、SQLite URL、其他非 PostgreSQL URL 以及非 201 主机；启动后
`GET /health` 会返回数据库后端类型，便于确认连接的是 201 PostgreSQL。
`PURSLYX_DEBUG` 和 `PURSLYX_AUTO_VERIFY_LOCAL` 只用于本地开发，正式部署应接入邮件验证并
关闭这两个开关。

## 页面入口与产品范围

根路径 `/` 是公共首页；正式端从 `/app/login` 或 `/app/register` 进入，登录后按身份进入独立页面：
求职端 `/app/seeker/*`、招聘端 `/app/recruiter/*`，授权账号另有 `/app/admin/*` 管理页面。
浏览器脚本确认链接仍使用 `/job-pool/items?browser_draft_id=...`。

所有页面共用同一份 201 PostgreSQL API 和会话，不需要 Node.js 构建。匹配池、改写、岗位版、面试、
任务状态以及管理员日志均通过独立页面访问。邮件服务、外部模型、分布式队列和压力测试属于生产部署能力，
不由本地开发配置代替。

启动 8001 后可用本机 Chrome 自动验证真实多页导航与两类账号主流程：

```bash
PURSLYX_BASE_URL=http://127.0.0.1:8001 node scripts/e2e_web_201.mjs
```

脚本只创建随机本地测试账号，不读取或输出《本地开发环境.md》中的密码；管理员写操作仍需调用方显式注入权限凭据。
