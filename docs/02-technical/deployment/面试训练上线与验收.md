# 面试训练上线与验收

更新：2026-10-05。代码已实现；本次交付不执行生产迁移或部署。

## 1. 上线边界

- 新会话固定 interview-rubric-v2，反馈 v5、总结 v3。旧记录不删除、不回填，已入队的旧任务继续按旧规则执行；新版列表与面试趋势不展示旧场次。
- 三个主问题、每题至多一次追问，完整且有效才生成个人练习指数。重答独立、免费且每题最多一次成功，失败重试原任务和原答案，不改变原指数或用户场次。
- 不包含语音、计时和联网事实检索。专业诊断是需核实提示，模型质量验收使用脱敏样例，不将其宣传为权威事实核查。

## 2. 本地检查和隔离演练

在仓库根目录执行：

```sh
.venv/bin/pytest -q
.venv/bin/ruff check src/server/app migrations tests scripts/smoke_interview_coaching_201.py
```

在 src/web 执行 npm test、npm run typecheck、npm run build。

真实 PostgreSQL 验收脚本为 `scripts/smoke_interview_coaching_201.py`，使用既有 201 配置但不输出连接凭据。执行：

```sh
.venv/bin/python scripts/smoke_interview_coaching_201.py
```

脚本仅创建两个随机 coaching_test_<32 位十六进制> Schema，子进程通过 PGOPTIONS 限定 search_path。测试拒绝非此命名或不匹配的实际 Schema，分别检查全新迁移链和从 0010 旧结构增量升级；alembic check 验证 ORM 一致，检查旧记录版本仍为空且正文未变。

API/Worker 演练覆盖三题正式流程、并发领取与幂等、无用户用量扣减、模型成本、预算拒绝、失败原任务重试、跨账号隔离、删除来源、暂停 Worker 后的迟到写回及 7/14/30 天趋势。finally 只移除本次成功创建的临时 Schema 和合成数据，不碰现有 Schema。

常规 pytest 默认跳过这些 PostgreSQL 集成测试，由上述脚本独立执行。模型覆盖是本地合成样例和模拟 OpenAI 结构化响应，不调用真实付费模型，也不上传用户回答。

## 3. 生产迁移和发布（另行安排）

1. 明确目标环境、备份与应用版本，检查 Alembic 当前版本及未处理旧任务。不要取消旧任务来完成升级。
2. 在批准的发布窗口执行 alembic upgrade head，新增 0011 的会话版本列、训练表及任务枚举；确认旧会话未被回填为 v2。
3. 更新并重启 API 与 Worker，避免旧 Worker 遇到新训练任务。前端和 API 同批发布；检查新任务中文标签和训练结果链接。
4. 新建脱敏练习检查三种题型、引用、异常重试和总结；完整/提前结束后做一次训练，验证原回答、总结、指数、场次额度未变。检查任务中心、删除及旧链接说明。
5. 对真实供应商的结构化 Schema/输出上限兼容性和专业诊断效果另做受控验收，不使用真实简历或付费账号数据作样例。

日志只保存请求、账号、会话、问题、训练、任务 ID、实际规则版本、阶段和异常类型。评价异常显示“评价暂未完成”，不能显示成用户缺失或零分；前端保留请求 ID 便于定位。
