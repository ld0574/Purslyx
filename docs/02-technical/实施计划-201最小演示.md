# 实施计划：201 最小演示

目标：明天用一条稳定、可解释、可复跑的链路讲清楚 SDD 开发过程。原则是只补能直接验证闭环的内容，不把今天变成完整平台冲刺。

## 今天收口

| 顺序 | 工作 | 完成标志 |
| --- | --- | --- |
| 1 | 运行基线 | 服务只接受 PostgreSQL URL；启动变量来自 `本地开发环境.md`，不使用 SQLite。 |
| 2 | 数据与 API | 201 上 `create_all` 平滑补齐当前演示模型；认证、版本、分析、用量和报告接口可调用。 |
| 3 | 关键边界 | 版本归属、分析输入类型、CSRF、幂等、跨账号隔离、删除后旧入口已验证。 |
| 4 | 产物 | PDF 可生成、可下载、A4 渲染无方框；浏览器脚本有失败本机草稿和登录后续传路径。 |
| 5 | 任务闭环 | PostgreSQL outbox、租约、过期恢复和本地 Worker 可用；默认仍可内联执行。 |
| 6 | 证据 | `pytest`、正式 `smoke_201.py`、Worker 201 验证和测试记录写入仓库。 |

## 明天现场节奏（建议 8 分钟）

1. 先打开 `/health`，指出 `201 + PostgreSQL`，说明环境口径不是本地 SQLite。
2. 打开 `/`，输入演示简历和 JD，点击“确认资料并生成匹配报告”，展示最短可视化路径。
3. 回到 Feature Spec，指出这不是“先写页面”，而是先定义草稿、版本、证据和验收。
4. 打开 Swagger `/docs` 或展示 `smoke_201.py`，顺着正式 API 讲 `documents → versions → job-pool → analyses`。
5. 展示报告中的能力分、覆盖率、逐条依据和条件状态，强调分数由代码规则计算。
6. 展示任务、用量和 `Idempotency-Key`：重复请求只返回原任务，失败可释放预留。
7. 最后运行一次冒烟脚本，展示 201、PDF、浏览器去重、303、面试恢复、跨账号和删除断言。

## 现场故障降级

| 故障 | 处理 |
| --- | --- |
| 201 不可达 | 不改数据库配置；说明环境依赖，展示已提交的代码和测试结果。 |
| 页面接口失败 | 直接运行 `smoke_201.py`，它只走 HTTP 正式接口并打印最小结果。 |
| 邮箱验证未完成 | 本地演示进程开启 `PURSLYX_AUTO_VERIFY_LOCAL=true`；不现场接 SMTP。 |
| 浏览器平台页面变化 | 不把平台 DOM 兼容说成已验收，演示手动 JD 或脚本的待上传草稿契约。 |
| PDF 版式异常 | 保留原版本，重新导出；不手动修改数据库里的版本正文。 |

## 明确后置

真实 OpenAI 调用、Celery/Redis 生产队列替换、SMTP、并发压测、全量管理员页面、BOSS/猎聘真实 DOM 联调和正式迁移工具。明日只展示本地 PostgreSQL Worker；这些生产化工作可以按现有接口和模型继续实施，但不阻塞 SDD 闭环。
