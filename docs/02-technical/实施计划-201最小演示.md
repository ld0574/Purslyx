# 实施计划：201 完整工作台演示

目标：明天用一套可操作、可解释、可复跑的完整前端工作台讲清楚 SDD 开发过程。前端页面全部可进入，
现场按时间挑一个模块深讲；主链路和边界用 201 PostgreSQL 冒烟证据兜底。

## 今天收口

| 顺序 | 工作 | 完成标志 |
| --- | --- | --- |
| 1 | 运行基线 | 服务只接受 PostgreSQL URL；启动变量来自 `本地开发环境.md`，不使用 SQLite。 |
| 2 | 数据与 API | 201 上 `create_all` 平滑补齐当前演示模型；认证、版本、分析、用量、报告、改写、岗位版、面试和管理接口可调用。 |
| 3 | 关键边界 | 版本归属、分析输入类型、CSRF、幂等、跨账号隔离、删除后旧入口已验证。 |
| 4 | 完整前端 | 求职、招聘和授权管理端页面全部接通；包含草稿审核、匹配池、报告跟进、改写、岗位版、面试、用量、统计、反馈和日志筛选。 |
| 5 | 产物 | PDF 可生成、可下载、A4 渲染无方框；浏览器脚本有失败本机草稿和登录后续传路径。 |
| 6 | 任务闭环 | PostgreSQL outbox、租约、过期恢复和本地 Worker 可用；默认仍可内联执行。 |
| 7 | 证据 | `pytest`、正式 `smoke_201.py`、Chrome 多页面 E2E、Worker 201 验证和测试记录写入仓库。 |

## 明天现场节奏（建议 8 分钟）

1. 先打开 `/health`，指出 `201 + PostgreSQL`，说明环境口径不是本地 SQLite。
2. 登录正式工作台，快速扫一遍完整菜单：求职端或招聘端，再看授权账号的管理菜单。
3. 选择一个模块深讲：推荐“匹配池 → 报告 → 待核实事项”，也可改讲“改写 → 岗位版 PDF”或“面试恢复”。
4. 回到 Feature Spec，指出这不是“先写页面”，而是先定义草稿、版本、证据和验收。
5. 打开 Swagger `/docs` 或展示 `smoke_201.py`，顺着正式 API 讲 `documents → versions → job-pool → analyses`。
6. 展示任务、用量和 `Idempotency-Key`：重复请求只返回原任务，失败可释放预留；其他页面作为已接通的可操作入口保留。
7. 最后运行一次冒烟脚本，展示 201、PDF、浏览器去重、303、面试恢复、跨账号和删除断言；需要证明前端时再运行 `node scripts/e2e_web_201.mjs`。

## 现场故障降级

| 故障 | 处理 |
| --- | --- |
| 201 不可达 | 不改数据库配置；说明环境依赖，展示已提交的代码和测试结果。 |
| 页面接口失败 | 直接运行 `smoke_201.py`，它只走 HTTP 正式接口并打印关键结果。 |
| 邮箱验证未完成 | 本地演示进程开启 `PURSLYX_AUTO_VERIFY_LOCAL=true`；不现场接 SMTP。 |
| 浏览器平台页面变化 | 不把平台 DOM 兼容说成已验收，演示手动 JD 或脚本的待上传草稿契约。 |
| PDF 版式异常 | 保留原版本，重新导出；不手动修改数据库里的版本正文。 |

## 明确后置

真实 OpenAI 调用、Celery/Redis 生产队列替换、SMTP、并发压测、BOSS/猎聘真实 DOM 联调、带管理员凭据的写操作浏览器回归和正式迁移工具。
明日只展示本地 PostgreSQL Worker；这些生产化工作可以按现有接口和模型继续实施，但不阻塞 SDD 闭环。
