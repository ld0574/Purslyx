## 1. 模块目标与边界

用户模块负责账号全生命周期中首版已确定的部分：邮箱密码注册、邮箱验证、密码重置、Web 会话、篡改猴受限会话、固定求职／招聘身份，以及独立的后台角色与权限。

注册身份在创建时确定，之后没有修改接口；后台角色只能授予管理权限，不能改变注册身份或业务资料归属。首版支持账号暂停和恢复，不把账号注销当作已完成能力。用户模块不读取简历、JD 或报告正文；管理端用户详情只组合注册、状态、用量和活动概要。

## 2. 目录与组件

| 组件 | 建议位置 | 职责 |
| --- | --- | --- |
| `AuthService` | `modules/users/service.py` | 注册、验证、登录、退出、重发验证、找回和重置密码 |
| `SessionService` | 同上 | 创建、校验、轮换、撤销 Web 会话 |
| `BrowserAuthService` | 同上 | 一次性授权码、受限浏览器会话和 scope 校验 |
| `AdminUserService` | 同上 | 管理端用户搜索、概要读取、暂停与恢复 |
| `RoleService` | 同上 | 角色权限组合、账号角色授予与撤销 |
| `CurrentIdentity` | `modules/users/dependencies.py` | 从会话解析账号、固定身份和实时后台权限 |
| `UserRepository` | `modules/users/repository.py` | 用户模块表的账号限定查询、条件更新和行锁 |
| `PasswordHasher`、`TokenCodec` | `integrations/security/` | Argon2id、随机秘密生成和摘要；原始令牌只返回一次 |

模块模型只映射 `accounts`、`account_tokens`、`web_sessions`、`browser_auth_codes`、`browser_sessions`、`admin_roles`、`admin_permissions`、`admin_role_permissions`、`account_admin_roles`。安全与审计事件由日志模块持有，用户 Service 通过追加端口写入。

## 3. 对外接口

| 使用者 | 方法与路径 | Service 用例 | 关键要求 |
| --- | --- | --- | --- |
| 公开 | `POST /api/v1/auth/register` | `register` | 选择一次 `seeker` 或 `recruiter`；重复邮箱返回中性结果 |
| 公开 | `POST /api/v1/auth/verify-email`、`/resend-verification` | `verify_email`、`resend_verification` | 令牌一次性；验证成功原子发放试用次数 |
| 公开 | `POST /api/v1/auth/login`、`/logout` | `login`、`logout` | 登录后更换会话；退出立即撤销 |
| 公开 | `POST /api/v1/auth/forgot-password`、`/reset-password` | `request_reset`、`reset_password` | 响应不暴露账号是否存在；重置成功撤销旧会话 |
| 已登录 | `GET /api/v1/me` | `get_current_account` | 返回固定注册身份、验证／账号状态和当前有效后台权限 |
| Web 与脚本 | `POST /api/v1/auth/browser-codes`、`POST /browser-auth/exchange`、`DELETE /browser-auth/session` | `issue_browser_code`、`exchange_browser_code`、`revoke_browser_session` | 来源与 nonce 绑定；只返回一次受限令牌；不复用 Web Cookie |
| 管理端 | `GET /api/v1/admin/users`、`/admin/users/{id}` | `search_users`、`get_user_summary` | 需要 `admin.users.read`；不返回私有业务正文 |
| 管理端 | `PUT /api/v1/admin/users/{id}/status` | `update_account_status` | 需要 `admin.users.manage_status`；revision 防并发，注册身份只读 |
| 管理端 | `GET/POST /api/v1/admin/roles`、`PUT /admin/roles/{id}` | `list_roles`、`create_role`、`update_role` | 需要 `admin.roles.manage`；内置超级管理员角色不可编辑 |
| 管理端 | `PUT /api/v1/admin/users/{id}/roles` | `replace_account_roles` | 不能自改、越权授权或移除最后一个超级管理员 |

篡改猴登录同步用 Web 会话签发的一次性授权码换取浏览器会话。签发接口要求 Web CSRF；换取接口校验固定产品来源、目标窗口和 nonce；撤销接口只撤销当前浏览器会话。不得复用 Web Cookie，也不得扩大 `browser_sessions.scope_version=1` 的权限。

## 4. Service 与用例

| 用例 | 输入 | 输出 | 协作模块 |
| --- | --- | --- | --- |
| 注册 | 规范化邮箱、密码、注册身份 | 待验证账号和中性发送结果 | 日志记录安全事件；SMTP 事务后发送 |
| 验证邮箱 | 原始令牌 | 激活账号、当前身份适用的初始用量 | 用量原子发放试用批次；日志记录完成 |
| 登录／恢复 | 邮箱密码或 Web 会话 | `CurrentIdentity` | 日志记录成功、拒绝、限频和会话签发 |
| 重置密码 | 一次性令牌、新密码 | 新密码版本和已撤销会话数 | 日志记录重置与会话撤销 |
| 浏览器授权 | Web 身份、产品域来源、nonce | 一次性授权码；随后换取受限令牌 | 匹配池只接受该会话上传本人岗位草稿 |
| 管理用户 | 筛选、目标账号、期望版本 | 脱敏概要或新账号状态 | 日志同事务保存前后值 |
| 管理角色 | 目标角色／账号、权限集合、理由、幂等键 | 生效的权限版本 | 日志同事务保存审计 |

所有下游模块依赖 `CurrentIdentity`，从服务端会话确定 `account_id` 和 `registration_role`。请求体中的账号、角色或 owner 字段不参与授权。

## 5. Repository 与数据访问

- 邮箱先做统一的大小写和空白规范化，再用有效账号唯一索引查找；接口仍返回中性文案。
- 会话查询同时校验摘要、状态、过期时间和账号状态。权限查询同时过滤账号角色、角色和权限的有效状态，不缓存超过一次请求。
- 管理用户列表只选择邮箱、注册身份、账号状态、时间和跨模块提供的聚合概要，不联表读取业务正文。
- 授权关联没有数据库外键。写入时显式读取并锁定账号、角色、权限；ORM 关系明确 `primaryjoin`，禁止依赖关系赋值绕过校验。
- 所有内部 ID 只留在 Repository 和 Service；响应使用 `public_id`。

## 6. 状态、事务与锁顺序

账号状态为 `pending_verification → active ↔ suspended`。注册身份没有状态转换。Web／浏览器会话为 `active → revoked` 或 `active → expired`，不可重新激活；验证和重置令牌消费后不可恢复。

关键事务遵循以下顺序：

1. 注册：写账号和验证令牌，提交后发送邮件；邮件失败不回滚账号，可重发并撤销旧令牌。
2. 验证：锁令牌 → 锁账号 → 标记验证成功 → 调用用量模块锁定／创建余额并发放试用 → 追加安全事件。
3. 重置：锁令牌 → 锁账号 → 更新密码版本 → 撤销有效 Web 会话 → 追加安全事件。
4. 角色变更：锁操作者账号 → 目标账号 → 角色 → 权限 → 授权关系 → 同事务追加管理审计。
5. 暂停：锁目标账号 → 更新状态与 revision → 撤销全部会话 → 追加审计；不得写注册身份。

并发管理操作携带基础 `revision`。版本不一致返回 409 并要求刷新；不能用最后写入覆盖权限变化。

## 7. 异步任务与模块协作

邮件发送发生在数据库提交之后，可通过 outbox 或专用可重试发送记录补偿。登录限频可以使用 Redis，但账号状态、令牌消费和会话有效性以 PostgreSQL 为准。过期令牌与会话由维护任务批量转态或清理，读取路径不能等待清理才判定失效。

用户模块向其他模块提供三个稳定端口：`require_identity`、`require_registration_role`、`require_admin_permission`。向匹配池提供浏览器会话 scope 校验，向用量提供已验证账号与固定身份，向日志提供操作者和安全事件元数据。用户模块不调用业务模块 Repository。

## 8. 权限、错误与安全

| 业务码 | HTTP | 场景与处理 |
| --- | --- | --- |
| `AUTH_INVALID_CREDENTIALS` | 401 | 邮箱或密码错误，响应不区分原因 |
| `AUTH_EMAIL_UNVERIFIED` | 403 | 引导重发验证邮件 |
| `AUTH_ACCOUNT_SUSPENDED` | 403 | 撤销会话并停止业务访问 |
| `AUTH_TOKEN_INVALID_OR_EXPIRED` | 410 | 验证／重置令牌无效、过期或已消费 |
| `AUTH_SESSION_EXPIRED` | 401 | 清理本地状态并重新登录 |
| `AUTH_BROWSER_SCOPE_FORBIDDEN` | 403 | 浏览器令牌调用了岗位草稿以外能力 |
| `ADMIN_PERMISSION_DENIED` | 403 | 当前有效权限不足 |
| `ADMIN_ROLE_CONFLICT` | 409 | revision 过期、自改、越权或最后超级管理员保护 |

密码只存 Argon2id 摘要；会话、验证、重置及浏览器秘密只存摘要。Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax`；写请求检查 Origin 和 CSRF。认证日志不保存密码、令牌、Cookie、完整 IP 或请求正文。

## 9. 测试与待确认项

必须覆盖注册身份固定、重复邮箱中性响应、验证令牌并发消费、重复验证只发一次试用、密码重置撤销旧会话、暂停即时失效、两账号隔离、浏览器授权码重放、scope 越权、管理员自改／越权和最后超级管理员保护。

集成测试使用 PostgreSQL 18 验证唯一索引和锁竞争，不以 SQLite 代替。上线前还需冻结 Web 会话、验证、重置、浏览器授权码与浏览器会话的具体有效期，并冻结浏览器握手消息 Schema。
