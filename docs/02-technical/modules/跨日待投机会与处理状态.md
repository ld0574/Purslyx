# 跨日待投机会与处理状态

更新：2026-10-11，处理规则 `job-handling-v1`。替代首页“今日投递建议”；不修改 `application-recommendation-v1` 匹配评分或分类规则。

## 清单与统计边界

首页按上海自然日显示含今天的近 30 天完成匹配结果，默认未处理（待投、待核实）。已处理为本人确认已投、不感兴趣；可切全部、四类模型建议以及岗位／公司关键词。模型建议与本人处理状态独立。

每个来源选择最新可读、未删除、账号归属及输入资料有效的报告，再按报告完成时间筛选。损坏、空结果和失败任务不遮住旧有效报告。旧岗位今天完成匹配可以进入；早于范围的记录仍在岗位池，不删除、不自动设为已处理。

候选全量流式读取，去重、筛选、分类计数后排序与分页，不提前截取 500 条。分类次序为优先投、可以尝试、先核实、暂缓投；同分类按报告完成时间降序、分析 ID 降序。默认 20 条，允许 1–100。游标绑定账号、筛选及日期，参数变化返回 409，要求刷新第一页。

列表展示报告使用的 JD 条件，薪资保留原文、未知写未披露，不用当前岗位字段补齐旧版缺失信息。同源新 JD 未重新匹配时，推荐标注旧版，详情仍只展示该报告冻结的 JD 和依据；仅追踪参数变化而 JD 条件与正文相同，不误报更新。重新匹配必须人工确认扣次，不自动重新调用模型。首页与岗位池共用详情弹窗，独立报告链接保留。

今日抓取／完成口径及自动处理的进行中、等待、失败统计单独保留，不用 30 天机会数替代今日事实。首页第一页继续轮询，后续页只提示变化，用户返回第一页刷新。

## 数据与接口

- `job_pool_items.opportunity_key` 为不可变来源键：浏览器使用平台和规范化来源 URL 的摘要，手动岗位使用自身公开 ID。详情路径中的岗位 ID 是身份，不受追踪参数影响；其他路径保留必要查询参数并规范排序。原平台访问 URL 和点击签名摘要保持不变。迁移只补标识，不读取正文、不按公司或标题合并；新旧记录使用相同身份规则。
- `job_handling_states` 按账号＋来源键唯一，保存四态、独立修订号和参考岗位；无记录视为 `pending`、修订 0。
- `job_handling_changes` 仅保存幂等、状态变更和引用元数据。历史幂等重试返回当前状态，不覆盖后续设备的修改；后续已有修改时不再提供旧操作撤销。
- `GET /api/v1/job-pool/opportunities`：`view=unhandled|handled|all`、`handling_status`、`tier`、`search`、`cursor`、`limit`。返回 `items / page / counts / range / timezone / version`，及原自动设置与今日进度。
- `PATCH /api/v1/job-pool/items/{id}/handling-status`：`status / base_revision / confirm_applied`。要求本人 Web 会话、CSRF、幂等键和账号写入锁。修订冲突 409，未明确确认已投 422；不调用模型、不预留或消耗次数、不改任务或报告。
- 岗位池列表和详情均返回 `handling`，列表支持 `handling_status`，不限制 30 天。原 `/recommendations` 接口保持兼容。

“本人确认已投”必须在弹窗勾选“我已在原平台提交”。去投递点击只记点击；从不推断已投。最近一次操作可按成功修订号撤销，已处理可恢复待投。失败保留原状态与草稿，展示请求 ID。
