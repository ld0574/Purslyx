## 1. 模块目标与边界

统计模块提供个人统计、用户主动产品反馈和授权管理端的全站概况。个人页面读取当前业务事实，保证点击或分析完成后可见；管理趋势读取按上海自然日生成的聚合，并明确数据截止时间。

“去投递点击数”只表示 Purslyx 成功记录并发起原 JD 跳转，不能命名为已投递数，也不能推断外部页面加载、平台回复、面试或 Offer。付费意愿只来自用户明确提交的反馈，不从按钮点击或功能使用推断。统计模块不改写业务状态，不复制简历、JD、回答或反馈正文到聚合表。

## 2. 目录与组件

| 组件 | 职责 |
| --- | --- |
| `PersonalStatsService` | 按固定身份返回本账号的当日事实统计 |
| `FeedbackService` | 用户提交、本人删除和授权人员查看反馈 |
| `AdminMetricsService` | 日期、身份和功能维度的站点概况与成本 |
| `DailyRollupService` | 以固定水位和规则版本重算日聚合 |
| `MetricSourceRegistry` | 声明每个指标的源表、时间字段、过滤条件和去重键 |
| `StatsRepository` | 反馈、聚合和只读业务事实查询 |
| `StatsWorkerService` | 定时聚合、迟到事件识别和指定日期补算 |

主责表为 `product_feedback`、`daily_metric_rollups`。个人点击和招聘分析数分别从匹配池的 `apply_click_events` 与可用招聘报告读取；成本和任务指标从任务、用量的追加事实读取。

## 3. 对外接口

| 使用者 | 方法与路径 | Service 用例 | 关键要求 |
| --- | --- | --- | --- |
| 已登录 | `GET /api/v1/stats/me` | `get_personal_stats` | 求职返回今日去投递点击；招聘返回今日候选人分析；带口径和时区 |
| 已登录 | `POST /api/v1/feedback` | `submit_feedback` | 主动反馈、可选业务上下文和明确付费意愿 |
| 管理端 | `GET /api/v1/admin/metrics` | `get_metrics` | `admin.stats.read`；限制日期范围，返回水位与规则版本 |
| 管理端 | `GET /api/v1/admin/costs` | `get_costs` | 已知成本和未知成本条数分开，不把未知当零 |
| 管理端 | `GET /api/v1/admin/feedback`、`/admin/feedback/{id}` | `list_feedback`、`get_feedback` | 授权读取反馈；详情再次鉴权且不返回上下文业务正文 |
| 管理端 | `PUT /api/v1/admin/feedback/{id}` | `update_feedback_status` | 授权标记已查看／关闭；revision 和前后值审计 |

首版不提供通用 `POST /api/v1/events`。核心指标直接读取服务端业务事实，避免客户端伪造任务成功、采用、导出或去投递；以后若确需页面行为分析，须另行评审事件白名单、数据用途、保留期限和表结构。

## 4. Service 与用例

**个人统计。** 根据固定身份在同一数据库快照读取上海当日范围。求职账号计数成功写入的去投递点击；招聘账号计数 `context_type=recruiter_single` 且完整可用的分析报告。返回 `from`、`to`、`timezone` 和指标名称，避免客户端误解。

**产品反馈。** 用户主动提交问题、建议、付费意愿或其他反馈。关联分析、改写、面试或导出时，先由主责模块校验资源属于当前账号且可见。付费意愿是独立受控枚举；未回答就是未回答。

**管理概况。** 按日期、注册身份和功能读取完成的日聚合，展示注册／活跃、任务成功／失败／重试、次数结算、去投递点击、改写采用段数、导出、完整／提前结束面试、反馈、再次使用、耗时和成本。成本接口按全部真实模型尝试归集，已知成本均值必须带成功结果分母。

**日聚合。** Worker 取得业务源水位，按 `daily-metrics-v1` 从源事实重算目标日期范围，再原子 upsert 聚合行。迟到事件触发受影响日期全量重算；P95 从原始样本重算，不能平均旧 P95，也不能在旧值上增量累加。

## 5. Repository 与数据访问

- 个人统计必须带 `account_id` 和有效业务状态，不读可能延迟的全站聚合。
- 全站聚合没有账号 ID 和私有正文；按日期、注册身份、功能和规则版本唯一。每次返回 `source_watermark_at`。
- `MetricSourceRegistry` 必须用代码常量登记源表和允许查询，不接受客户端传入表名、列名或任意指标表达式。
- 活跃、采用、完整面试和再次使用均从服务端事实及冻结规则计算。页面浏览类指标若无经评审的数据源，就不展示。
- 反馈详情和聚合查询分开；管理聚合只计数，不加载反馈正文。反馈删除立即阻断正文读取，历史无正文计数按保留规则处理。
- 日界线由 `Asia/Shanghai` 明确计算；数据库连接仍使用 UTC。

## 6. 状态、事务与锁顺序

反馈状态为 `new → reviewed → closed`，查看人和时间同时写入；用户删除后正文立即不可读，再异步清理。日聚合是可重算派生数据，revision 只表达同一规则与维度下的最新完整生成。

提交反馈时先验证账号和可选上下文，再插入反馈。管理查看／关闭锁定反馈并同事务追加审计。聚合 Worker 先计算临时结果，再以短事务按固定键 upsert 全部目标行和水位；中途失败不能暴露一半新、一半旧的同批结果。

统计查询本身不锁业务表，不与业务事务争用父资源行。需要一致范围时使用固定水位和合适的数据库快照，不跨多个无界查询拼接数字。

## 7. 异步任务与模块协作

匹配池提供点击和分析事实，简历提供改写采用和导出事实，面试提供完成类型，任务提供成功／失败／重试、耗时和模型调用，用量提供结算流水，用户提供注册身份，日志提供允许汇总的管理操作数量。各模块只暴露统计投影，不向统计模块开放写入。

定时聚合使用任务模块的免费任务，不占用户功能次数。失败告警后可安全重算。管理页面必须显示数据截止时间；个人统计不依赖聚合任务。

效果口径固定：求职核心完成是分析后采用至少一段改写并导出；招聘核心完成是单人分析后查看依据或待核实事项；7 日再次使用需标记观察完成和未观察满样本；完整面试只计 3 个主问题及汇总，提前结束单列。

## 8. 权限、错误与安全

| 业务码 | HTTP | 场景与恢复 |
| --- | --- | --- |
| `STATS_RANGE_INVALID` | 422 | 日期倒置、过长或超出允许范围 |
| `STATS_NOT_READY` | 503 | 聚合尚无完整水位，返回可用截止时间 |
| `STATS_PERMISSION_DENIED` | 403 | 缺少 `admin.stats.read` 或反馈查看权限 |
| `FEEDBACK_CONTEXT_NOT_FOUND` | 404 | 上下文资源不存在、不属于账号或已删除 |
| `FEEDBACK_CONTEXT_INVALID` | 422 | 上下文类型与资源组合不合法 |
| `FEEDBACK_CONTENT_INVALID` | 422 | 类型、长度、评分或付费意愿不合法 |
| `FEEDBACK_STATUS_CONFLICT` | 409 | 刷新反馈 revision 或修正状态流转 |

管理统计不返回账号私有正文、模型提示、文件、令牌或日志详情。小样本分组是否隐藏由上线隐私规则确定；在规则冻结前不公开可重新识别个人的细粒度交叉筛选。

## 9. 测试与待确认项

必须覆盖上海日界线、点击令牌去重、招聘报告只计完整可用、个人即时统计、迟到事件补算、同水位重复计算、P95 重算、未知成本、无成功结果时不算均值、反馈上下文越权、付费意愿不推断和普通账号无法访问管理端。

编码前需冻结 `daily-metrics-v1` SQL 口径、活跃事件集合、管理默认日期范围、刷新频率、细粒度隐私阈值，以及反馈列表与详情的字段范围。
