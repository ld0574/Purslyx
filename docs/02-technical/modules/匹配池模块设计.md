## 1. 模块目标与边界

匹配池模块负责浏览器侧当前 JD 获取、待确认岗位草稿、求职者私有岗位、双端单岗位分析、可核对证据、条件对照和“去投递”跳转。求职者每确认一条岗位便单独分析一条；不做后台爬取、公共岗位库、跨岗位推荐、自动投递或平台进度监控。

分析能力同时服务两个入口：求职报告必须关联私有匹配池岗位并从其详情进入；招聘单人报告关联本账号的一份 JD 和一位候选人简历，由“候选人简历”页面展示，不创建候选人池。两端共用评分规则、代码计算和证据校验。

## 2. 目录与组件

| 组件 | 建议位置 | 职责 |
| --- | --- | --- |
| `BrowserDraftService` | `modules/job_pool/service.py` | 校验受限会话、接收／去重草稿、确认与过期 |
| `JobPoolService` | 同上 | 私有岗位列表、详情、入池、待分析恢复和删除 |
| `AnalysisService` | 同上 | 双端分析创建、输入冻结、报告读取和重新分析 |
| `ScoringEngine` | `modules/job_pool/scoring.py` | 按规则版本用 Decimal 计算维度、总分和覆盖率 |
| `ConditionMatcher` | `modules/job_pool/conditions.py` | 岗位方向、地点、办公方式和薪资的确定性比较 |
| `EvidenceValidator` | `modules/job_pool/evidence.py` | 校验版本、稳定段落键、引用文字和来源类型 |
| `ApplyRedirectService` | `modules/job_pool/apply.py` | 签发点击令牌、链接白名单、幂等记录和 303 跳转 |
| 两站适配器 | `src/userscript/platforms/` | BOSS／猎聘 URL 识别、DOM 提取和页面状态面板 |
| `JobPoolRepository` | `modules/job_pool/repository.py` | 草稿、岗位、报告、证据、条件与点击事件的账号限定访问 |

主责表为 `browser_job_drafts`、`job_pool_items`、`analysis_reports`、`analysis_dimension_scores`、`analysis_requirement_results`、`analysis_evidence`、`analysis_condition_results`、`apply_click_events`。

## 3. 对外接口

| 使用者 | 方法与路径 | Service 用例 | 关键要求 |
| --- | --- | --- | --- |
| 已登录 | `POST /api/v1/analyses`、`GET /analyses`、`/analyses/{id}` | 创建、列表、详情 | 招聘单人分析或明确重新分析；固定输入版本 |
| 求职账号 | `POST /api/v1/job-pool/items` | `confirm_job` | 从浏览器草稿或手动 JD 入池；只保存可免费 |
| 求职账号 | `GET /api/v1/job-pool/items`、`/job-pool/items/{id}` | 列表、详情 | 返回分析状态、报告入口、原文和输入版本摘要 |
| 求职账号 | `POST /api/v1/job-pool/items/{id}/analyze` | `start_analysis` | 显式确认一次分析消耗；同输入执行幂等 |
| 求职账号 | `POST /api/v1/job-pool/items/{id}/go-to-apply` | `record_and_redirect` | CSRF＋一次性点击令牌；记录成功后 303 |
| 浏览器会话 | `POST /api/v1/browser/job-drafts`、`GET /browser/job-drafts/{id}` | `upload_browser_draft`、`get_browser_draft_status` | 只允许本人待确认草稿；上传本身不入池、不计次 |
| 资源所有者 | 通用删除影响与删除接口 | 预览、删除岗位／报告 | 立即关闭报告和跳转入口 |

浏览器草稿接口只接受用户模块签发的受限浏览器会话，不能读取简历、报告、用量、其他岗位或管理接口。字段级请求与响应随 `browser-job-capture-v1` 一起冻结。

## 4. Service 与用例

**自动获取。** 篡改猴只在 BOSS 和猎聘受支持的 JD 详情页运行。平台适配器等待关键 DOM 出现并短暂稳定，规范化 URL，提取标题、公司、正文和页面明确披露的地点／方式／薪资，再用 URL 摘要＋内容指纹防抖上传。字段缺失保留未知，不猜测。未登录时短期保存在脚本本机，完成 Purslyx 握手后续传。

**确认入池。** 自动获取只产生待确认草稿。用户在 Web 检查后，Service 创建或引用已确认 JD 版本，选择一条完整期望版本并创建私有岗位。若用户同时确认分析消耗、简历／期望齐全且次数可用，则在同一事务预留 1 次分析并创建任务；否则保存为待满足条件。

**双端分析。** 求职场景校验匹配池岗位、简历和期望；招聘场景校验招聘身份、候选人简历、JD 和可选的候选人明确期望。Worker 用模型拆分 JD 条目并判断证据，再由 `EvidenceValidator` 核对原文，`ScoringEngine` 按冻结规则计算分数，`ConditionMatcher` 独立比较条件。模型不能直接给出最终总分或覆盖率。

**去投递。** 页面从服务端取得与岗位绑定的一次性点击令牌。提交时只用岗位中已保存的链接，重新校验求职身份、归属、未删除、HTTPS 和平台域名；事件提交成功后返回 303。同一令牌重试不重复计数，记录失败或链接失效时不跳转。

## 5. Repository 与数据访问

- 草稿唯一键为账号、平台、规范化 URL 摘要和内容指纹；重复上传返回原草稿。原 URL 与 JD 正文属于私有内容。
- 私有岗位列表只读摘要和状态；完整 JD、证据引用与条件值按详情分开读取。已删除岗位使其报告和跳转接口同步不可见。
- 报告写入要求 4 个适用／不适用维度状态明确，实际权重合计为 1；能力分、覆盖率、条件对照和整体建议分别持久化。
- 所有证据引用同时限定 `account_id`、报告、资料版本和稳定段落键。允许受控空白规范化，不接受模型摘要冒充原文。
- 求职报告必须有 `job_pool_item_id`，招聘报告必须为空；Repository 仍需 Service 校验 `context_type` 与注册身份。
- 点击统计以 `apply_click_events.created_at` 转上海日期写入 `metric_date`；不从前端事件、浏览器回调或页面返回推断投递成功。

## 6. 状态、事务与锁顺序

浏览器草稿为 `awaiting_confirmation → confirmed` 或 `awaiting_confirmation → expired／failed`。私有岗位分析为 `awaiting_requirements → queued → running → ready`，运行失败为 `failed`；恢复原任务不创建新报告。报告为 `queued → running → available／failed`。

关键事务：

1. 草稿上传：校验浏览器会话、求职身份、平台与 URL → 按唯一键插入或返回原草稿；不接触用量和任务。
2. 入池分析：锁账号 → 草稿／JD／简历／期望 → 用量余额 → 任务 → 岗位／报告占位 → outbox，一次提交。
3. 招聘分析：锁账号 → JD／候选人简历／候选人期望 → 余额 → 任务 → 报告占位 → outbox。
4. 发布报告：锁来源父资源 → 任务 → 报告；校验代次、完整性和引用，写维度／证据／条件／建议，置可用并结算一次分析。
5. 去投递：锁岗位，校验当前链接摘要并插入点击事件；提交后才返回目标地址。
6. 删除：锁岗位／报告及活动任务，立即标记不可见并取消；事务后清理正文和检查点。

## 7. 异步任务与模块协作

浏览器会话由用户模块签发，确认 JD 和期望由简历模块提供，功能预留由用量模块完成，任务模块负责分析执行。匹配池 Worker 持有提示词、评分编排和报告完整性条件。面试只能读取可见报告和冻结资料；统计只读可用报告及点击事件。

分析工作流固定为：冻结输入 → 拆分去重要求 → 证据判断 → 引用校验 → 代码评分 → 代码条件比较 → 生成解释 → 整体完整性校验。资料不足以形成任何可评估条目或覆盖率为零时进入 `needs_input` 并释放用户次数；不会输出 `0 分` 假装已经完成。

修改简历或期望不改变旧报告。页面标记其未应用最新条件，用户明确重新分析后创建新输入快照、新任务和新报告，并再次计一次分析。

## 8. 权限、错误与安全

| 业务码 | HTTP | 场景与恢复 |
| --- | --- | --- |
| `JOB_CAPTURE_PAGE_UNSUPPORTED` | 422 | 脚本提示手动粘贴，不伪报完成 |
| `JOB_CAPTURE_SESSION_REQUIRED` | 401 | 本机保留草稿并引导登录同步 |
| `JOB_CAPTURE_SCHEMA_UNSUPPORTED` | 422 | 更新篡改猴脚本后重新上传 |
| `JOB_DRAFT_EXPIRED` | 410 | 重新获取或手动粘贴 |
| `JOB_ANALYSIS_REQUIREMENTS_MISSING` | 422 | 岗位保留待分析，补齐简历／期望 |
| `ANALYSIS_ROLE_MISMATCH` | 403 | 固定身份与分析上下文不符 |
| `ANALYSIS_EVIDENCE_INVALID` | 503 | 不发布报告，按任务恢复策略修正模型输出 |
| `ANALYSIS_INPUT_STALE` | 409 | 当前操作使用的基础版本已变化 |
| `APPLY_URL_UNSUPPORTED` | 422 | 不写点击、不跳转 |
| `APPLY_CLICK_CONFLICT` | 409 | 点击令牌与当前岗位／链接不一致 |

脚本不得读取招聘平台 Cookie、密码或账号凭据；Purslyx 浏览器令牌不能放入 URL、DOM、控制台或通用日志。服务端对 URL 做长度、HTTPS、允许域名和规范化检查，禁止开放重定向。JD 全部视为待分析数据，不能成为系统指令或触发任意工具。

## 9. 测试与待确认项

必须覆盖 BOSS／猎聘 URL 和 SPA 路由、DOM 延迟与重复渲染、未登录续传、授权过期、重复内容去重、字段缺失、手动粘贴、入池不分析、次数不足待分析、双端身份隔离、评分算例、引用越界、未知与差距区分、薪资口径、硬条件冲突、重新分析、点击令牌重试、错误域名和删除后跳转。

正式发布前需用真实两站页面冻结适配器版本、URL 白名单、内容指纹和草稿有效期；用脱敏研发／产品／运营／通用样例校准量表、覆盖率提示和结构化输出。本设计不宣称页面选择器或模型评分已经在两站生产页面完成验证。
