## 1. 模块目标与边界

日志模块提供三类管理查询：管理操作、登录安全和任务运行；同时负责短期日志导出以及无数据库外键情况下的每日引用完整性巡检。三类信息保留不同权限和数据范围，不合并成无类型的通用日志表。

管理审计与安全事件由对应业务流程追加；任务运行详情直接读取任务模块，不重复复制。日志不保存简历、JD、回答、反馈正文、密码、Cookie、令牌、密钥或文件内容。完整性巡检只报告孤儿、跨账号和已删除父对象仍可见的问题，不自动修改业务数据。

## 2. 目录与组件

| 组件 | 职责 |
| --- | --- |
| `AuditWriter` | 在业务事务内追加成功管理操作，在拒绝后独立追加拒绝事件 |
| `SecurityEventWriter` | 登录、限频、锁定、重置和会话签发／撤销事件 |
| `LogQueryService` | 三类日志独立鉴权、筛选、详情和脱敏投影 |
| `LogExportService` | 导出申请、状态、私有下载、到期与清理 |
| `IntegrityScanService` | 逻辑引用规则注册、只读扫描、异常批量写入和复查 |
| `LogRepository` | 审计、安全、导出、巡检运行和异常访问 |
| `TaskLogReader` | 从任务模块读取允许的任务、尝试、耗时和调用关联 |
| `LogWorkerService` | CSV／JSONL 导出、每日巡检和过期文件清理 |

主责表为 `admin_audit_events`、`security_events`、`log_exports`、`integrity_scan_runs`、`integrity_scan_findings`。任务运行日志仍由任务表提供。

## 3. 对外接口

| 方法与路径 | 权限 | Service 用例 |
| --- | --- | --- |
| `GET /api/v1/admin/logs/operations` | `admin.logs.operations.read` | 管理操作列表 |
| `GET /api/v1/admin/logs/security` | `admin.logs.security.read` | 登录安全列表 |
| `GET /api/v1/admin/logs/tasks` | `admin.logs.tasks.read` | 任务运行列表 |
| `GET /api/v1/admin/logs/{type}/{id}` | 对应类别查看权限 | 受限详情 |
| `POST /api/v1/admin/log-exports` | `admin.logs.export`＋对应类别查看权限 | 创建异步导出 |
| `GET /api/v1/admin/log-exports/{id}` | `admin.logs.export`＋对应类别查看权限 | 查询导出状态 |
| `GET /api/v1/admin/log-exports/{id}/file` | `admin.logs.export`＋对应类别查看权限 | 下载未过期私有文件并留审计 |

下载时再次检查申请人、类别权限、未过期状态和私有文件可用性。完整性巡检首版由定时任务和受控维护命令触发，不开放普通管理页面手动修复。

## 4. Service 与用例

**管理审计。** 角色、权限、账号状态和使用次数成功变更时，业务写入与成功审计处于同一事务，记录操作者、目标、动作、结果、理由、request_id 和白名单前后值。被权限或规则拒绝的请求不进入业务事务，可独立追加拒绝事件。

**安全事件。** 记录登录成功／拒绝、限频、账号锁定、密码重置、邮箱验证以及 Web／浏览器会话签发与撤销。未知邮箱与错误密码对外响应一致；日志中网络信息按降精度和带轮换盐摘要保存。

**查询与导出。** 列表按日期、账号、目标、结果和关联 ID 使用允许字段筛选。详情再次检查类别权限。导出固定时间范围、字段白名单和格式，创建任务、outbox、导出记录及审计；Worker 分页读取允许列，CSV 防公式注入，JSONL 每行带 Schema 版本。

**引用巡检。** 每日按规则版本和一致水位扫描所有登记的逻辑引用，检查目标存在、账号一致、用途正确以及删除父对象是否仍有可见子对象。异常只保存脱敏标识与分类，告警后由人工审核迁移修复，再新建复查运行。

## 5. Repository 与数据访问

- 审计和安全事件为追加事实，不提供普通更新／删除接口。前后值 JSONB 使用严格白名单 Schema，未知键默认拒绝。
- 日志列表只选择显示列；详情也不能返回原请求体、堆栈、提示词或业务正文。任务日志通过 `TaskLogReader` 的固定投影查询。
- 类别权限分别检查；拥有一种查看权限不自动拥有其他类别或导出权限。
- 导出文件使用简历模块私有文件能力中的 `log_export` 用途，必须由日志导出记录控制下载和到期，不能生成公开 URL。
- 引用规则以代码注册：来源表、引用列、目标表、账号列、可见条件和严重度。扫描器不接受数据库中存放的任意 SQL。
- 巡检明细保存内部关联所需 ID；管理响应使用受控标识，避免通过异常列表枚举其他账号正文。

## 6. 状态、事务与锁顺序

日志导出为 `queued → exporting → downloadable`，失败进入 `failed`，到期进入 `expired` 并立即禁止下载。巡检运行为 `queued → running → completed／failed`；异常为 `open → confirmed → resolved_after_recheck`，不能仅凭人工点击直接标记已解决。

管理变更锁顺序由业务模块决定，审计事件最后写入。日志导出创建顺序为操作者账号与权限 → 导出记录 → 任务 → outbox → 审计。每日巡检只读业务表，在固定快照完成扫描后批量追加异常并核对汇总数；不持有跨模块业务行锁。

导出到期时先条件更新状态阻断下载，提交后清理文件。清理失败只告警和重试，不恢复可下载状态。

## 7. 异步任务与模块协作

用户模块调用安全事件和角色审计端口，用量模块调用次数发放审计端口；其他需要管理写入的模块同样只能调用 `AuditWriter`。这些端口接受结构化白名单数据，不接受任意正文或完整请求字典。

任务查询由任务模块提供投影，内容删除后仍可保留无正文的状态、耗时、重试和成本关联。导出和巡检使用任务模块的免费任务，不改变用户功能次数。巡检发现问题后发送告警，但任何修复必须通过单独审核的数据迁移。

每个模块在新增逻辑 `_id` 引用、动态资源引用或可见性规则时，必须同时向 `IntegrityReferenceRegistry` 登记；迁移检查应阻止缺少巡检规则，或需要反向读取却既无索引也无明确免建理由的变更进入发布。

## 8. 权限、错误与安全

| 业务码 | HTTP | 场景与恢复 |
| --- | --- | --- |
| `LOG_PERMISSION_DENIED` | 403 | 缺少所选类别查看或导出权限 |
| `LOG_TYPE_INVALID` | 422 | 日志类别不在首版白名单 |
| `LOG_RANGE_INVALID` | 422 | 日期范围、筛选字段或行数上限不合法 |
| `LOG_EXPORT_NOT_READY` | 409 | 导出仍在排队或执行 |
| `LOG_EXPORT_EXPIRED` | 410 | 下载已到期，需按权限重新申请 |
| `LOG_EXPORT_FAILED` | 503 | 原筛选保留，可恢复任务 |
| `INTEGRITY_SCAN_FAILED` | 内部 | 告警并重试，不改业务数据 |
| `INTEGRITY_FINDING_STILL_PRESENT` | 409 | 复查仍发现异常，不能标已解决 |

所有管理接口每次请求重新鉴权，检查 CSRF、限制时间范围和分页大小。CSV 单元格以 `= + - @` 开头时做安全转义；导出文件短期保存、禁止公共缓存。安全日志中的网络与客户端信息只保留排障必需的最小值。

## 9. 测试与待确认项

必须覆盖各日志权限互不继承、成功业务与审计同事务回滚、拒绝事件、脱敏白名单、筛选和分页、详情越权、CSV 公式注入、导出重复提交／到期、资料删除后任务日志无正文，以及孤儿、跨账号、已删父对象可见三类巡检样例和只读保证。

编码前需冻结三类日志保留期、导出日期与行数上限、IP 降精度与摘要轮换、巡检频率／批量大小／告警渠道、规则注册格式，以及异常修复审批与复查流程。
