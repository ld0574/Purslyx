## 1. 模块目标与边界

简历模块负责两类账号的私有资料输入和版本：求职者自己的简历与多条岗位期望；招聘者的一份 JD、一位候选人简历及候选人明确提供的期望。它还负责求职者的事实补充、逐段改写、岗位版编辑与 PDF。

确认后的资料、期望和岗位版使用不可变版本。分析、改写、面试和导出必须引用明确版本，不能在任务执行时读取“当前最新内容”。求职分析报告由匹配池模块持有并从匹配池页面进入；招聘单人报告也由匹配池的分析能力持有，但由“候选人简历”页面展示。简历模块不拥有分析报告状态、功能余额或通用任务租约。

## 2. 目录与组件

| 组件 | 职责 |
| --- | --- |
| `DocumentService` | 创建文本／文件资料、列表、详情、私有文件下载和标题更新 |
| `DocumentParseService` | 建立解析草稿、发起免费解析任务、校验模型结构输出 |
| `DocumentVersionService` | 用户修正、确认并生成不可变资料版本和稳定段落键 |
| `PreferenceService` | 多条岗位期望、完整条件版本、默认指针和候选人期望来源 |
| `FactService` | 本人补充事实及确认版本，不回写原始简历 |
| `RewriteService` | 冻结输入、生成逐段建议、证据校验和采用／撤回记录 |
| `ResumeVariantService` | 岗位版内容、模块排序、排版白名单和乐观锁版本 |
| `ExportService` | 同版本成品键、异步 PDF、私有下载和过期清理 |
| `ResumeDeletionService` | 删除影响预览、即时撤销访问、任务取消和清理编排 |
| `ResumeRepository` | 本模块所有表的账号限定查询、版本号分配和行锁 |

主责表为 `stored_files`、`documents`、`document_drafts`、`document_versions`、`job_preferences`、`job_preference_versions`、`resume_facts`、`resume_fact_versions`、`resume_rewrites`、`resume_rewrite_segments`、`resume_rewrite_evidence`、`resume_segment_decisions`、`resume_variants`、`resume_variant_versions`、`resume_exports`。

## 3. 对外接口

| 资源 | 方法与路径 | Service 用例 | 关键要求 |
| --- | --- | --- | --- |
| 导入 | `POST /api/v1/documents` | `create_document` | 文本或受支持文件；账号身份决定用途 |
| 解析 | `POST /api/v1/documents/{id}/parse` | `start_parse` | 返回 202 和免费任务；同输入幂等 |
| 确认 | `POST /api/v1/documents/{id}/versions` | `confirm_version` | 校验草稿 revision、类型、来源和稳定段落结构 |
| 资料 | `GET /api/v1/documents`、`/documents/{id}`、`/documents/{id}/file` | 列表、详情、下载 | 账号限定；文件不可公共缓存 |
| 期望 | `GET/POST /api/v1/preferences`、`GET/PUT/DELETE /preferences/{id}` | 期望增删改查 | 每条独立保存完整组合；修改创建新版本 |
| 事实 | `POST /api/v1/facts` | `confirm_fact` | 免费；只接受本人明确补充并记录来源 |
| 改写 | `POST /api/v1/rewrites`、`GET /rewrites/{id}` | `start_rewrite`、`get_rewrite` | 求职身份；确认一次改写消耗；逐段返回依据 |
| 岗位版 | `POST /api/v1/resumes`、`GET /resumes`、`/resumes/{id}`、`POST /resumes/{id}/versions` | 创建、读取、保存版本 | 受限内容与样式；并发编辑使用基础版本 |
| 导出 | `POST /api/v1/exports`、`GET /exports/{id}/file` | `start_export`、`download_export` | 免费但限频；预览与下载使用同一成品 |
| 删除 | `GET /api/v1/{resource}/{id}/deletion-impact`、`DELETE /api/v1/{resource}/{id}` | 影响预览、确认删除 | 本模块处理 documents、resumes、rewrites、facts；影响变化返回 409 |

字段级请求与响应由后续 OpenAPI 定稿；接口不得接受 `account_id`，版本引用均使用 `public_id`。

## 4. Service 与用例

**导入确认。** 创建 `documents` 和文件元数据后，文件流写入私有存储；文件完整可读才允许创建解析任务。Worker 输出必须通过对应 Pydantic／JSON Schema，生成 `document_drafts`。用户修正草稿时使用 revision，确认后一次性创建 `document_versions`，后续修改另建新版本。

**岗位期望。** 求职账号可有多条 `job_preferences`，例如前端与后端各一条；每次提交在同一父记录下生成完整 `job_preference_versions`。默认项切换锁定账号下相关父记录，保证最多一个有效默认。招聘场景必须关联候选人资料，只保存候选人明确提供的条件和来源。

**事实与改写。** 事实先保存并由用户确认。改写只接收已确认简历版本、目标 JD／分析上下文、选定段落和已确认事实版本；Service 与匹配池核对报告账号及输入版本，再调用用量和任务建立执行。Worker 校验所有证据引用，结果按段落保存。用户采用、保留或编辑均追加决策；采用后再次编辑必须撤回原“已采用”状态。

**岗位版与导出。** 岗位版从明确简历版本和可选改写创建，内容、顺序与排版参数共同生成不可变版本。导出使用岗位版版本＋模板＋字体版本作为成品键；同键已有可用 PDF 时复用。HTML 模板只接受白名单样式和转义后的文本，不加载用户脚本或任意外网资源。

## 5. Repository 与数据访问

- 所有读取从认证账号开始，以 `account_id`、用途和未删除父对象共同限定。招聘账号不能把候选人简历当作本人求职简历使用。
- 文件元数据与物理文件分两阶段就绪；数据库状态为 `available` 且业务父对象可见时才允许流式下载。
- 版本号在父记录行锁内取下一个值，依赖数据库唯一约束处理最终竞态。已确认版本不执行正文更新。
- 期望查询一次返回一条完整版本，禁止使用跨记录 `COALESCE` 拼接地点、方式或薪资。
- 动态引用 `analysis_report_id`、`job_pool_item_id`、`async_task_id` 在写入时调用主责模块校验；本模块 Repository 不直接查询或更新其表。
- 列表只选择摘要字段；正文、结构 JSONB 和文件按详情需要单独加载，避免后台和日志查询误取私有内容。

## 6. 状态、事务与锁顺序

资料为 `importing → available` 或 `importing → failed`；草稿为 `parsing → unconfirmed → confirmed`，失败可由原输入重试。改写为等待任务、生成中、可查看或失败；段落采用状态由决策流水计算。导出为排队、渲染、可下载、失败或过期。实际枚举值以数据库设计为准。

关键事务：

1. 确认资料：锁账号 → `documents` → 待确认草稿；校验 revision 和内容 Schema，创建不可变版本并标记草稿已确认。
2. 保存期望：锁账号 → `job_preferences`；校验完整条件与基础 revision，写新版本并更新父记录。切换默认时同时锁定账号的有效期望。
3. 发起改写：锁账号 → 简历／事实版本 → 用量余额 → 任务；同事务写改写占位、预留、输入引用和 outbox。
4. 保存岗位版：锁岗位版父记录，校验基础版本与所有采用决策仍有效，再写不可变版本。
5. 删除：锁顶层资源及已计算影响集合，若集合摘要改变返回 409；标记不可访问、取消任务、释放未结算预留并写清理 outbox。

文件写入、模型请求和 Chromium 渲染均在事务外。外部动作失败保留数据库状态和可重试输入。

## 7. 异步任务与模块协作

| 任务 | 队列 | 结算 | 成功条件 |
| --- | --- | --- | --- |
| 资料解析 | AI | 不扣功能次数，计模型成本 | 待确认草稿通过 Schema 且可读取 |
| 逐段改写 | AI | 完整可读建议后结算 1 次改写 | 引用、段落和事实校验全部通过 |
| PDF 导出 | 导出 | 免费，受频率限制 | 私有文件可读、页数记录且无截断错误 |
| 正文／文件清理 | 维护 | 不计次 | 所有待清理内容不可读并记录清理时间 |

任务模块持有调度和尝试；简历模块持有业务结果。用量模块处理改写预留和结算。匹配池提供报告和目标 JD 上下文，面试只读取确认版本。Worker 发布任何结果前重新校验来源未删除、账号一致和执行代次有效。

## 8. 权限、错误与安全

| 业务码 | HTTP | 场景与恢复 |
| --- | --- | --- |
| `DOCUMENT_FORMAT_UNSUPPORTED` | 422 | 提示转换或粘贴文本 |
| `DOCUMENT_PARSE_FAILED` | 422／503 | 保留原输入，按可重试标记操作 |
| `DOCUMENT_VERSION_CONFLICT` | 409 | 保留本地内容，刷新基础版本 |
| `PREFERENCE_INCOMPLETE` | 422 | 指出未知、倒置区间或缺少口径字段 |
| `REWRITE_EVIDENCE_INVALID` | 422 | 不发布无依据建议，允许补充事实后重试 |
| `RESUME_VERSION_CONFLICT` | 409 | 重新合并当前岗位版 |
| `EXPORT_RENDER_FAILED` | 503 | 原版本不变，可恢复原任务 |
| `RESOURCE_DELETION_CHANGED` | 409 | 重新展示最新影响集合 |

文件名和 MIME 由服务端重新检查，存储键不暴露绝对路径。文件响应使用鉴权流和禁止公共缓存。PDF 渲染进程无特权，限制 CPU、内存、时间和网络；日志不记录正文、文件编码或本地路径。

## 9. 测试与待确认项

必须覆盖 PDF／DOC／DOCX／文本、空白／加密／扫描件／超限文件、草稿冲突、确认版本不可变、跨账号下载、求职与候选人用途混用、多条期望不串值、未知与不限区分、倒置薪资、改写引用越界、采用后编辑撤回、连续保存岗位版、长文本分页、预览下载同版本和删除期间 Worker 迟到。

目标 ARM 环境需用固定 Chromium 与中文字体验证 PDF。编码前还需冻结文件大小／页数限制、内容与排版 JSON Schema、模板和字体版本，以及导出文件与未确认草稿的保留时长。
