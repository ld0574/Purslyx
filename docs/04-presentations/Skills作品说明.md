# Purslyx：证据化求职 Skills

## 一句话介绍

Purslyx 是一个真正可执行的求职 Skill：从 BOSS 直聘／猎聘岗位页获取 JD，围绕用户已确认的简历事实完成岗位匹配、事实约束改写和 STAR 面试练习，并让每个 AI 结论都能回到原文证据。

## 这件作品解决什么问题

普通“简历优化”工具容易把岗位关键词堆进简历，普通面试题生成器也容易问出与岗位无关的问题。Purslyx 把三个动作串成一个闭环：

1. 岗位页面抓取完成后直接进入私有匹配池，用户集中收集岗位，再在需要时选择输入开始匹配。
2. AI 按 JD 要求逐条寻找简历证据，并按公开规则输出参考分；服务端重新校验引用并计算最终能力分，不让模型用摘要直接拍最终分数。
3. AI 改写只能使用原文和用户补充事实；新增数字没有证据时会被拒绝。
4. 面试题针对当前岗位缺口生成，回答后按 STAR（Situation、Task、Action、Result）反馈，最多一次关键追问，最后给出 STAR 复盘。

## 创新点与可核验性

| 亮点 | 实际行为 | 验收方法 |
| --- | --- | --- |
| 浏览器到工作台闭环 | Tampermonkey 在岗位详情页识别 JD，直接写入私有匹配池，不自动投递 | 打开 BOSS／猎聘详情页，看到 Purslyx 面板并完成同步，岗位出现在匹配池 |
| 证据约束匹配 | 模型只提交状态和引用键；服务端只接受真实简历段落，并用固定规则计算分数 | 删除或修改引用键时，结果降级为“待确认” |
| 不编造的改写 | 改写证据包含原文和用户事实；新数字不在事实中会触发 `MODEL_OUTPUT_INVALID` | 提供含“99 个项目”的模型假输出，任务失败且原文不变 |
| STAR 面试闭环 | 每道主问题要求 STAR，反馈指出四个维度缺口，追问只发生一次 | 用短回答触发追问，再回答追问后进入下一题或总结 |
| 可恢复的真实任务 | 模型请求、预算、任务状态和失败原因分开记录，刷新页面可继续或重试 | 断开模型配置后重试，看到可读错误，输入和回答仍保留 |

## 2–3 分钟演示脚本

1. 登录 Purslyx，展示首页的“证据化求职 Skill”和浏览器助手安装入口。
2. 在岗位详情页点击“同步 Purslyx”，展示岗位已写入匹配池与来源 URL；进入匹配池选择简历和岗位期望并等待分析。
3. 打开报告，先看 AI 洞察，再展开某条能力要求，展示对应的简历原文引用和固定评分规则。
4. 进入“事实与改写”，选一段经历和一个用户补充事实，展示原文、AI 建议、理由和证据；说明没有事实就不会凭空增加数字。
5. 进入面试，展示三道针对岗位缺口的 STAR 问题；提交一个缺少结果的回答，展示 AI 的 Action/Result 缺口与一次追问。
6. 完成或提前结束，展示 STAR 总结（S/T/A/R 四格）和下一步练习建议。

## 成功样例

- JD：`熟悉 React 和 TypeScript，负责跨团队项目交付。`
- 简历事实：`负责 React 项目开发，与设计和后端协作完成上线。`
- 预期：React 有证据；TypeScript 或跨团队交付如果没有原文依据，显示“待确认”；面试题要求说明本人行动和结果。

## 异常样例

- JD 或简历为空：提示缺少输入，不生成看似确定的结论。
- 用户回答“我做过这个项目”：AI 指出缺少 Situation、Action 或 Result，并生成一次具体追问。
- 模型改写加入原文和事实之外的数字：服务端拒绝结果，原文和用户事实不被覆盖。
- 大模型配置或价格缺失：任务进入可读失败状态，显示重试动作，不扣除未交付的功能次数。

## 运行与模型配置

生产环境在服务器 `/data/purslyx/.env` 配置真实模型，至少包括：

```dotenv
PURSLYX_MODEL_PROVIDER=openai
PURSLYX_MODEL=gpt-4.1-mini
OPENAI_API_KEY=<your-key>
PURSLYX_MODEL_INPUT_USD_PER_MILLION=0.40
PURSLYX_MODEL_CACHED_INPUT_USD_PER_MILLION=0.10
PURSLYX_MODEL_OUTPUT_USD_PER_MILLION=1.60
```

配置后执行：

```bash
sudo scripts/release.sh deploy
```

当前适配器使用 OpenAI-compatible Chat Completions API 的严格 JSON Schema；使用其他服务时，`OPENAI_BASE_URL` 应填写 API 根地址（通常以 `/v1` 结尾），并确认其支持 `/chat/completions` 和结构化输出。
