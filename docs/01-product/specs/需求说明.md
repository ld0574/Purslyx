## 1. 产品定位与目标用户

Purslyx 是面向求职者和招聘方的 AI 助手，核心价值是 **有依据的岗位匹配、真实自然的简历表达，以及针对性面试准备**。注册时选定求职或招聘身份；两端各自导入资料，共用匹配规则，不建立公开人才库、公开岗位市场或站内投递平台。求职者可保存自己确认的岗位，形成私有匹配池。

| 用户 | 当前问题 | 产品交付的价值 | 付费验证方向 |
| --- | --- | --- | --- |
| 求职者 | 不清楚经历与岗位的关系，也可能遇到岗位方向、地点或薪资不合适；简历表达模板化，制作岗位版本与准备面试耗时 | 同时看清能力与求职条件是否匹配，用真实经历生成可编辑、可导出的岗位版简历，并练习相关面试问题 | 是否愿意为有效的分析、改写和面试练习购买使用次数 |
| 招聘方 | 简历表达模糊，候选人期望与岗位条件可能错位，核实能力和准备面试耗时 | 对一个岗位、一个候选人给出能力依据、已知期望与岗位条件的对照、待核实事项及面试问题 | 是否愿意为分析质量和节省的评估时间购买使用次数 |

岗位类型开放，首批重点验证研发、产品、运营，覆盖应届生和有工作经验的求职者。课程项目、校园活动、兼职和正式工作均可成为经历依据；不将缺少实习等同于没有能力。招聘端首版服务单个招聘使用者，不包含企业团队协作与组织权限。

两类客户同时验证付费意愿，商业模式为 **免费试用＋按 AI 功能购买使用次数**。首版开放注册、限额内测，先记录价值和成本；套餐售价与真实支付在后续验证中确定，不承诺录用结果、真实投递成功率或账号零风险。

## 2. 完整功能与优先级

**P0：首版基础能力；P1：首版增强能力；P2：完整留存的后续需求。** P0 与 P1 只表示实施顺序，均为七天首版验收必交范围；两站岗位入池、去投递跳转与点击统计、完整多轮面试不得因工期不足而作为合格首版的可选项。

| 编号 | 功能 | 优先级 | 确定的范围与边界 |
| --- | --- | --- | --- |
| F01 | 账号身份与云端资料 | P0 | 邮箱＋密码注册时选定求职或招聘身份，邮箱验证后使用对应工作台；首版身份固定，另一身份须用另一邮箱注册独立账号；保存、查看、删除本账号资料与历史，账号间隔离 |
| F02 | 简历与 JD 导入 | P0 | 简历支持文本、文字型 PDF、DOC、DOCX；JD 支持粘贴，提取岗位名称、工作地点／方式与薪资范围。解析后可检查、纠正，再进入分析 |
| F03 | 岗位匹配分析 | P0 | 一份 JD 对照一份简历及已确认的求职期望，输出能力匹配总分、固定维度解释、原文依据、条件匹配情况、缺口与整体建议，两端规则一致 |
| F04 | 事实补充与自然改写 | P0 | 从缺口问题收集真实经历，按岗位生成建议；支持比较原文、手动编辑、选择采用，保留原始资料 |
| F05 | 简历编辑与 PDF | P0 | 一个初始模板；模块拖动排序，字体、字号、间距和加粗可调；内容自动流动、分页，导出岗位版 PDF |
| F06 | 招聘方单人深入分析 | P0 | 查看 F03 的分析，结合该候选人明确提供的求职期望与岗位条件，得到待核实事项和针对性面试问题，辅助人工评估 |
| F07 | 岗位匹配池与浏览器采集 | P0／P1 | 篡改猴自动同步 Purslyx 登录状态；求职者打开 BOSS 直聘或猎聘受支持的 JD 详情页后，自动识别并获取当前岗位，直接写入私有匹配池并提示完成。抓取入库不绑定简历／期望、不消耗次数；用户点击“匹配”时再选择输入并逐条打分。未登录时短暂保留本机草稿并在登录同步后继续；页面不支持或失败时可粘贴，未选择输入或使用次数不足时保留待分析岗位 |
| F08 | 文字面试练习 | P0／P1 | P0 至少 3 个针对性问题及一轮文字回答反馈；P1 连续问答、追问与结束后的汇总反馈 |
| F09 | 用量与试用次数控制 | P0 | 按 AI 功能计次，展示余额和消耗，服务端校验、预留、扣减、释放；控制频率、并发和全站用量 |
| F10 | 模型成本记录 | P0 | 按账号、注册身份、功能记录模型、用量、耗时、失败重试及估算成本，支持汇总和复核 |
| F11 | 试用与付费意愿验证 | P0 | 记录两端的核心流程完成、再次使用、建议采用、面试完成与明确的付费意愿反馈 |
| F12 | 求职期望与岗位条件 | P0 | 可保存多条相互独立的岗位期望；每条同时保存岗位名称、工作地点、办公方式、薪资范围及条件强度，分析前选择其中一条生成快照，不跨条拼接字段；与 JD 披露条件逐项对照并影响整体建议，未知与不限分开记录 |

| L02 | 校招渠道与时间提醒 | P2 | 校招信息渠道、时间线、网申和宣讲会窗口、重点岗位截止提醒 |

| L04 | 多岗位比较与优先级 | P2 | 在私有匹配池逐条打分之外，对多个岗位做跨岗比较与投递优先建议；不将匹配分包装成录用概率 |
| L05 | 投递辅助与完整进度管理 | P2 | 辅助填写、本人确认的投递操作，以及跨平台的回复／面试／Offer 阶段管理；首版只记录从匹配池前往原岗位的跳转，不追踪平台结果 |
| L06 | 市场薪资参考与定薪建议 | P2 | 在可靠市场信息、实际经验等依据上提供薪资参考和定薪建议；双方已提供范围的基础对照由 F12、F03 在 P0 完成 |
| L07 | 企业岗位画像 | P2 | 将模糊招聘描述整理为可编辑的职责、能力要求和评估标准 |

| L09 | 可复用评估标准与筛选 SOP | P2 | 评估模型、结构化面试题库、初筛／复筛／终面阶段管理及复用；首版不开放自定义评分权重 |
| L10 | 多模板与高级版本管理 | P2 | 模板切换、内容库复用、多岗位版本比较与批量生成，其他导出格式作为后续扩展 |
| L11 | 付费使用次数包与交易 | P2 | 套餐、订单、支付、使用次数发放、交易查询与售后处理，按试用结果验证价格 |

实施可先完成固定身份账号与使用次数、条件确认、双端分析、事实改写及 PDF，再接入私有匹配池、两站浏览器输入、去投递跳转及完整多轮面试，最后联验管理端；这些阶段顺序不改变首版验收范围。若七天内任一 P0/P1 项未完成，应如实列为未交付，不能以只支持 BOSS 直聘或只完成一题反馈宣称首版完成。资料隔离、真实依据、使用次数正确性和错误恢复同样是必交条件。

首版云端可保存各个岗位的简历结果与私有匹配池；匹配池只收录浏览器在用户打开的受支持 JD 详情页自动获取、或用户手动填写并最终确认的岗位，每条独立打分，不后台发现全站岗位或进行跨岗推荐。L10 指内容库、批量产出和高级版本对比，不影响首版保存和再次打开已有岗位版简历。

## 3. 核心流程与结果要求

### 求职期望与岗位条件（P0）

首次分析前展示求职期望确认步骤。求职者可保存多条岗位期望并设置一条默认值；每条都是岗位方向、地点、办公方式、薪资和条件强度组成的独立条件组合。入池或分析前选择其中一条并可修改本次使用值，系统生成不可变快照，不把前端方向的地点与后端方向的薪资拼成一组。各项均提供填写入口，也允许明确选择“不限／面议”或“暂不填写”。未填写表示未知，不等同不限，不阻止查看已有能力分析，但不能据此声称条件全部匹配。

| 条件 | 求职者／候选人提供的期望 | 岗位侧记录的条件 |
| --- | --- | --- |
| 岗位名称 | 一个或多个期望岗位名称、可接受的岗位方向；明确提供职级时一并保存 | JD 原始岗位名称、实际职责和明确披露的职级，保留来源 |
| 工作地点与方式 | 一个或多个可接受城市，以及现场办公、混合办公、远程工作的接受情况；异地意愿须本人明确 | 实际工作地点、办公方式，以及远程岗位明确披露的地域限制；总部地址不默认等于工作地点 |
| 薪资范围 | 期望下限、上限，币种、月薪／年薪、税前／税后口径；允许选择面议 | 招聘范围、币种、周期、税前／税后口径及已明确的发薪月数，保留原始描述；面议单独标记 |

每项已填写的期望可标记“必须符合”或“可协商”；未选择强度时按“可协商”处理，不能擅自设为硬门槛。默认薪资填写口径为人民币、税前月薪，提交前明确展示；导入资料未写明的币种、周期、税制和发薪月数不得自动补成默认值。倒置或不可读的区间提示修正，修正前不参与数值对照。

用户确认的期望独立于简历经历保存，不自动写入导出的简历。不得从现居地、上一份岗位或当前工资推断未来期望，也不得把 JD 条件反向填成求职者期望。招聘端只记录当前候选人明确提供的信息及来源；缺少时待核实，不套用招聘使用者自己的求职设置。

### 条件如何参与匹配

**结果分为“能力匹配总分＋求职条件对照＋整体建议”。** 能力分回答是否有相关能力和经历；岗位方向、地点与薪资回答双方条件是否适合。条件冲突不改写成能力低分，也不能被高能力分掩盖。整体建议必须同时引用两类结果，不额外虚构一个将未知信息混算的综合百分比。

| 条件 | 对照规则 |
| --- | --- |
| 岗位名称 | 结合名称、职级与实际职责判断方向，不能只按关键词或标题相等判断；名称近义但职责一致可说明对应关系，同名但职责不同仍提示方向差异 |
| 地点与方式 | 在用户明确接受的城市、办公方式范围内对照；多个可接受城市任一符合即可。可接受远程不等于接受任意异地现场办公，远程的地域限制未明确时需确认 |
| 薪资 | 在币种、周期和税前／税后口径一致时比较。招聘上限低于期望下限，提示“披露范围低于期望”；区间跨过期望下限，提示“可能达到，需确认”；招聘下限已达到期望下限，说明这一事实；整体高于期望上限不因无区间交集而判为不匹配。招聘范围不是实际 Offer 承诺 |
| 不可比或缺失 | 一方未提供、面议、口径不同或换算信息不足时标为“待确认／暂不可比较”，不记为零分或默认符合。仅在币种、税制相同且固定发薪月数明确时做月／年换算并展示算式，不估算汇率、税率、奖金或未明确的额外月薪 |

已知条件满足时可结合能力给出建议；标为“可协商”的冲突提示沟通重点；标为“必须符合”的冲突应突出显示，整体结论为“当前不优先，先确认或调整条件”，仍保留能力分析。未知项影响结论的完整性，不能给出“全部符合”。招聘端同样只提示冲突，不自动淘汰候选人。

例如：期望杭州现场办公且必须符合，JD 要求上海现场办公，即使能力分高也提示地点冲突；期望税前人民币月薪 20–30K，岗位为同口径 15–25K，提示部分范围可能达到、需确认实际预算，不能判成完全符合；岗位为 35–40K 时不因高于期望上限判为不匹配。

### 求职者

注册时选择求职身份、验证邮箱 → 进入求职工作台 → 确认简历与期望岗位、地点／方式、薪资范围 → 篡改猴自动同步 Purslyx 登录状态 → 打开 BOSS／猎聘受支持的 JD 详情页后自动获取并直接写入匹配池，或手动粘贴 JD → 在匹配池点击“匹配”并选择本次简历、岗位期望，确认一次分析消耗后逐条打分 → 查看能力依据、条件对照和缺口 → 补充事实 → 确认消耗并生成改写 → 编辑、选择采用 → 调整版式、保存、导出 PDF。可基于同一岗位和简历开启文字面试；从匹配池点击“去投递”打开原岗位详情后，由用户在平台自行决定是否投递。

### 招聘方

注册时选择招聘身份、验证邮箱 → 进入招聘工作台 → 导入一份 JD 与候选人简历 → 检查解析内容与岗位条件，记录候选人已明确提供的期望 → 确认消耗一次分析次数并分析 → 查看能力得分、维度、原文依据与条件冲突 → 查看待核实事项与面试问题 → 保存评估参考。候选人的经历缺口列为待核实内容，不由招聘者或 AI 擅自补写为候选人的事实。

### 各环节的输入与输出

| 环节 | 输入 | 必须交付的结果 |
| --- | --- | --- |
| 导入解析 | 粘贴文本或支持的简历文件、JD 文本 | 可阅读、可纠正的内容，以及岗位名称、实际地点／办公方式、薪资披露条件；可回溯到页码、段落或粘贴原文的来源标识 |
| 岗位入池 | 浏览器在用户打开的受支持 JD 详情页自动获取的岗位，或用户手动填写的当前岗位 | 浏览器获取完成提示；直接写入的私有岗位条目；用户点击匹配并选择输入、确认本次分析消耗后生成独立任务和评分，资料或使用次数不足时保留待分析状态 |
| 期望确认 | 期望岗位、地点／方式、薪资范围及条件强度 | 默认期望和本次分析所用条件；保留明确不限、可协商、必须符合与未知的区别，招聘端保留候选人信息来源 |
| 匹配分析 | 用户检查后的简历、JD 及本次求职期望 | 能力总分、固定维度与权重、得分和原文解释；三项条件对照、冲突与未知项；综合两类结果的整体建议与下一步 |
| 事实补充 | 缺口问题与用户的回答 | 单独保存的用户补充记录；可成为新依据，不覆盖原始简历，不自动触发付费功能 |
| 简历改写 | 所选段落、JD、已有事实与用户补充 | 原文与建议对照、改写理由；可修改、采用或保留原文，不擅自加入未提供的数据或成果 |
| 简历导出 | 已确认的岗位版简历与排版设置 | 对应当前版本的 A4 PDF，页数按内容生成，中文正常、无截字或重叠 |
| 招聘面试准备 | 当前 JD 与单人分析 | 与具体岗位要求、简历经历或缺口关联的面试核实问题，留给招聘方判断 |
| 文字面试 | JD、当前简历、用户逐轮回答 | 问题、回答、针对性追问和反馈记录；反馈指出回答依据、遗漏与具体改进方向 |
| 去投递跳转 | 用户点击私有岗位的“去投递” | 服务端核验并记录账号、岗位、平台与服务端记录点击的时间；重复请求不重复计数，统计名称为“去投递点击数”，不代表外部页面加载或已提交简历 |

**匹配解释规则**：两端采用同一套固定且公开的能力维度、权重、条件对照与规则版本，能力总分须能按展示的维度得分与权重复核。每条重要结论关联岗位要求、简历原文、已确认期望或用户补充，不输出无依据的肯定结论。具体能力量表由后续技术设计固化并用研发、产品、运营案例校验；条件对照遵循上文规则。

至少区分“有依据支持”“待确认，当前资料未提供”“存在明确差距”三种结果。未知项不作为“没有能力”的事实结论；信息不足时说明分数的资料边界，不能给出可靠分析时提示补充内容。不得以年龄、性别评分，不自动录用或淘汰候选人，不把匹配分换算为回复、面试或 Offer 概率。

用户编辑或补充经历、修改期望条件不会自动消耗使用次数，也不会暗中替换已有分析。要求重新分析或生成另一版改写时，先展示对应消耗；历史结果保留所依据的简历、JD 与期望条件版本。修改期望后标记旧报告尚未应用新条件，避免把旧结论当作新内容的分析。

**面试规则**：首版按一场 3 个主问题、每题最多一次追问组织。追问承接当前回答；用户可提前结束或中断后继续，报告明确已完成和未回答的部分，不对未回答内容编造反馈。一题回答反馈可作为开发阶段的中间验收，不构成七天首版最终验收。

**浏览器侧规则**：篡改猴自动同步 Purslyx 登录状态，但不读取或复制 Purslyx 密码、招聘平台账号、密码、Cookie 等凭据。它只在用户打开 BOSS 直聘或猎聘受支持的 JD 详情页时，等待页面内容稳定后自动识别一次，获取当前岗位标题、公司、规范化来源链接、工作地点／方式、薪资原文和可取得的职责／要求，直接写入匹配池并提示“岗位信息获取完成”；未披露或未成功获取的条件标明待补充，不伪造默认值。相同平台、规范化链接和内容不重复生成岗位。未登录时先短暂保留本机草稿，提示登录，并在登录状态同步后自动继续。

自动获取直接加入匹配池，但不绑定简历／期望、不预留或消耗分析次数。用户点击匹配时再选择输入，页面才展示自动分析将消耗 1 次分析机会；未选择简历／期望或使用次数不足时保留待分析条目，不暗中调用模型。首版不后台发现或批量抓取岗位，不辅助填写或提交申请；遇到验证、页面不支持或解析失败时明确显示状态并提供重试或手动粘贴，不伪报成功。

匹配池只为来源有效的岗位展示“去投递”。用户点击后，服务端核验本账号岗位与已保存的原 JD 链接，记录事件并发起跳转；同一次点击的重试不重复记数。链接被判无效或事件记录失败时不发起跳转，也不计数。服务端无法确认外部页面最终加载。点击数只表示从 Purslyx 发起前往原岗位的次数，不能写作“已投递简历数”；用户是否实际提交、平台是否回复均不由首版监控或推断。手机端也可从 Web 点击该入口。

## 4. 商业化、使用次数与成本

### 功能计量与免费范围

| 功能 | 一次消耗覆盖的范围 | 内测初始次数 |
| --- | --- | --- |
| 分析 | 一份 JD 与一份简历及本次求职期望的完整能力分析、条件对照、缺口和补充问题；招聘端包含面试核实问题 | 20 次 |
| 改写 | 用户确认提交的一次改写请求，可涵盖多个选定段落 | 20 次 |
| 面试 | 一场面试的 3 个主问题、每题最多一次追问和结束后的反馈；提前结束仍属于同一场 | 5 场 |

求职账号使用分析、改写和面试三类使用次数；招聘账号只有分析次数，不展示改写与面试次数。每个账号完成邮箱验证后按注册身份领取一次适用的试用次数；不同账号不共享余额，登录、重复验证或删除资料不重置使用次数。初始数量可配置，只是内测试用值，不代表已确定的付费套餐或价格。

手动导入和检查、填写事实、设置或修改期望条件、编辑文字、模块排序、保存岗位、查看历史、浏览器获取岗位和 PDF 导出不消耗 AI 使用次数。匹配池岗位入池后自动分析属于一次分析，确认前展示消耗；条件对照包含其中，不另计使用次数。剩余次数用尽仍可保存岗位和处理已有资料。每次计次操作在执行前展示功能、本次消耗和该类剩余次数；首版不展示虚假的付款入口或暗中切换到收费。

### 扣减、失败与恢复

| 情况 | 使用次数行为 | 用户看到的结果 |
| --- | --- | --- |
| 余额足够，发起分析／改写 | 服务端校验并预留对应功能的 1 次，成功交付完整且可查看的结果后扣减 | 展示执行状态、结果和更新后的余额 |
| 面试开场 | 预留 1 场，开场问题成功生成后扣减 | 本场后续回答、追问、汇总或恢复不另扣使用次数 |
| 余额不足或受到频率／并发／全站预算限制 | 不发起新的 AI 调用、不新增扣减 | 说明限制并保留输入，可查看历史、手动编辑或导出 |
| 分析／改写失败，或面试尚未成功开场 | 释放预留使用次数，不记为成功消耗 | 给出失败原因和可执行的重试入口 |
| 重复点击、响应丢失或网络中断 | 同一执行任务只结算一次；先查询原任务状态 | 已成功则恢复原结果，仍在执行则继续等待，明确失败后可重试 |
| 已开场面试中途失败或退出 | 保留已开始的一场及记录，不再扣除面试次数 | 回到原会话继续，已交付的问题与回答可恢复 |

“恢复或重试原任务”和“主动生成新分析／新版本”须区分。后者是新的 AI 功能使用，确认消耗后计次；前者不得因为重复请求产生额外扣减。使用次数校验、并发控制、预留与结算由服务端完成，不能仅依赖前端按钮状态。

开放注册提供邮箱验证、账号请求频率、并发与全站用量预算控制。限值由运营配置、服务端执行；触达限制时保存草稿，不把限额提示显示为分析成功。

### 成本与商业验证

每次 AI 执行记录所属账号、固定注册身份、功能、关联任务、模型标识、可取得的输入／输出用量、耗时、成功／失败状态、重试关系和估算成本。估算注明币种和价格依据，缺失字段标为“未知”，不当作零成本；成功、失败及重试调用均计入成本统计。管理统计只向授权人员开放，不暴露给其他使用者。

| 指标 | 记录口径与用途 |
| --- | --- |
| 首次核心流程完成率 | 分角色观察首次发起分析的账号：求职端完成分析、采用改写并导出 PDF；招聘端获得单人报告并查看依据或面试核实内容 |

首版管理端须有可用的站点概况、用户管理、角色权限、使用次数发放和日志管理页面；报表以这些确定口径为准，不要求复杂自定义报表。两端分别验证效果与付费意愿，不把试用次数使用率或生成数量直接作为收入证明。后续依据真实反馈和成本验证次数包价格，再实现订单、支付和售后；首版不虚构价格、转化率或盈利预测。

### 管理端边界

管理端从已登录账号菜单进入，分为“站点概况”“用户管理”“角色权限”“次数管理”“日志管理”，对应统计、用户、用量和日志模块。只有获授权的账号可见；菜单隐藏不代替接口鉴权。求职／招聘是注册身份，首版固定；后台角色与权限是独立授权，不改变该身份、资料归属或可用的求职／招聘功能。

首版后台权限至少区分查看用户、管理角色与权限、发放使用次数、查看站点概况、查看操作日志、查看安全日志和查看任务日志。受控维护命令初始化首位超级管理员，不能由注册接口自行获得。超级管理员可在“角色权限”维护后台角色的权限组合，并在用户详情为账号授予或撤销已有角色；角色变更需再次核验操作者权限，超级管理员内置角色不可编辑，管理者不能改自己的角色、授予超过自身的权限，也不能移除最后一个超级管理员。用户管理可按邮箱、注册身份与状态检索账号和查看概要，不提供浏览私有简历正文或修改注册身份的入口。

次数管理只对目标账号身份适用的功能追加正数次数，不直接覆盖余额；提交时显示用户、功能、发放次数和原因，并记录操作者、时间、幂等键与变更前后数值。重复提交不得重复发放。站点概况按上海日期展示注册用户及身份分布、分析／改写／面试使用、去投递点击数、成本和产品反馈；点击数仍不代表真实投递。日志管理按权限分为管理操作、登录安全与任务运行，可按日期、账号、对象、结果和关联 ID 筛选并查看必要详情；导出也记录操作者和筛选摘要。日志不保存或展示简历、JD、回答、密码、Cookie、令牌等正文。无权限时各页面及接口明确拒绝。

## 5. 数据、异常与视觉边界

- **资料分类**：原始简历、岗位版简历、多条岗位期望及其版本、JD、招聘候选人及其已知期望、分析与面试历史按账号归属，并保留必要的来源关联；分析保存当次期望与岗位条件的版本，支持重新登录后继续查看与处理。
- **删除与隔离**：删除前说明影响的关联资料，确认后不可通过历史入口或原链接继续读取已删除内容。不同账号不能访问彼此的正文、文件、报告或余额；用量台账不保存简历正文，删除资料不重置使用次数。
- **解析边界**：首版处理文字型 PDF、DOC 和 DOCX；扫描件、图片、加密文件、空白或不可读内容明确提示转换或粘贴文本。失败时不生成空报告、不消耗分析使用次数。
- **排版边界**：首版是模块流式编辑器，支持顺序和样式调整、A4 自动分页，不做任意坐标画布。长文本或不合适设置须给出可修正的提示，不能静默截断；PDF 与当前已确认版本一致。
- **真实表达**：保留事实、减少空话与模板化措辞，用户可修改后再采用。系统不得把缺口、推测或招聘方的假设写成候选人已完成的经历。
- **错误恢复**：解析、模型调用、登录失效、使用次数校验和浏览器摘取失败时，说明当前状态并保留可恢复的输入，提供修改、重试、继续登录或手动粘贴入口。
- **视觉规则**：沿用 A：品牌蓝 `#1264E8`、机会黄 `#FFD438`、成功绿 `#39CEA0`、提醒橙 `#FF8A3D`。状态须配文字；信息不足提示使用 `#FFF7F2` 浅底、橙色竖线和深橙色标题 `#964016`，表达补充建议。未采用的改写不提前显示完成，再次编辑后撤回已采用状态。

技术栈、模型和邮件服务、云端存储、评分量表、接口、导出实现、部署与未来支付服务进入后续技术设计；须落实本文的输入输出、公开规则、资料隔离和使用次数行为，不改变已确认的产品范围。本轮不编写接口定义或为尚未接入的服务指定参数。

| M4-05 | 局部微调影响整体版式 | F05（P0）模块排序、加粗、样式调整后自动重排 |

## 7. 验收标准

以下是实现后的验收场景，不是当前已通过的测试报告。使用虚构或脱敏的研发、产品、运营 JD，至少包含应届生和有经验者两类资料；同时准备长简历、信息不足、格式错误及两个不同账号的样例。

| 编号 | 场景 | 可观察的通过标准 |
| --- | --- | --- |
| AC01 | 求职者完成核心流程 | 保存至少两条不同岗位方向的独立期望，从支持格式导入简历；先连续抓取或保存岗位，再从匹配池点击“匹配”选择其中一条期望和一份简历并确认消耗一次分析，从岗位详情打开完整能力报告、条件对照和输入版本；补充事实并确认消耗生成逐段改写，查看理由与依据，编辑采用后调整岗位版模块和排版、预览并导出 PDF，原文仍可区分 |
| AC02 | 招聘方单人深入分析 | 一个 JD 和一份候选人简历得到能力评分、条件对照、缺口及面试核实问题；缺少候选人期望时标明未知，不套用招聘者设置；重要结论可追溯，不自动淘汰或录用 |
| AC03 | 评分与事实边界 | 同样简历、JD、期望条件及规则版本在两端使用相同规则，能力总分可按维度复核；缺少描述标为待确认，明确差距有依据；年龄、性别与期望薪资变化不改变能力分，条件变化影响条件对照与整体建议 |
| AC04 | 改写真实性 | 用户未提供的业绩数字、实习和项目不得被补写；补充记录可追溯，手动编辑后不继续显示旧的已采用状态 |
| AC05 | 排版与 PDF 稳定 | 长段落、跨页项目、中文与英文混排、模块换序及字号／间距调整后无文字丢失、重叠或截断；桌面和手机打开 PDF 内容及分页一致 |
| AC06 | 完整文字面试 | 生成 3 个相关主问题、支持每题最多 1 次承接回答的追问与反馈并给出汇总；提前结束明确未答部分，中断可恢复；续答不再扣一场 |
| AC07 | 两站岗位入池与自动匹配 | 篡改猴可自动同步 Purslyx 登录状态；打开 BOSS 直聘（P0）或猎聘（P1）受支持的 JD 详情页后，无需点击获取按钮即可自动取得当前岗位标题、正文、规范化来源链接及已披露地点／方式、薪资原文，直接写入匹配池并提示完成。同页同内容不重复生成；未登录时保留本机草稿并在登录同步后继续。自动获取不绑定简历／期望、不计次；用户在匹配池点击“匹配”后再选择输入并确认一次分析消耗。资料或使用次数不足时岗位保持待分析，页面不支持或失败时可重试或手动粘贴，不自动投递 |
| AC08 | 导入与解析失败 | 文本、文字型 PDF、DOC、DOCX 可检查并修正；扫描件、图片、加密或空文件给出明确处理方式，失败不产生空分析报告或扣费 |
| AC09 | 账号身份、邮箱验证与资料恢复 | 注册时选择求职或招聘身份，首版不可切换；另一身份须用另一邮箱注册；未验证邮箱不发试用次数，验证后仅发一次；重新登录可恢复本账号适用的资料、版本及面试记录 |
| AC10 | 删除与跨账号隔离 | 两个账号不能读取或修改对方文件、正文、分析、面试、使用次数；确认删除后不能从旧入口读取已删除内容，删除不重置余额 |
| AC11 | 正常使用次数消耗 | 求职账号默认得到分析 20 次、改写 20 次、面试 5 场；招聘账号默认得到分析 20 次；执行前显示适用功能的消耗和余额，成功后只结算对应一次，条件对照不额外计次 |
| AC12 | 失败、重复与并发 | 原任务失败释放预留，成功任务因重复点击或响应丢失只扣一次；恢复面试不再开扣一场；并发预留不超出可用使用次数，耗尽时不启动新 AI 调用 |
| AC13 | 免费操作与全站限制 | 手动编辑、事实填写、期望设置与修改、查看历史、保存岗位、排序、浏览器获取岗位与 PDF 导出不消耗 AI 使用次数；入池后的自动分析须先确认一次消耗，命中频率、并发或预算限制时有提示且输入可恢复 |
| AC14 | 成本与统计 | 可按账号身份和功能复核用量、耗时、失败重试和估算成本，未知不当零；可按日查询前往投递跳转次数、核心流程完成、采用、面试、再次使用及明确的产品意愿反馈，按同一口径计算单位结果成本；跳转不写成平台已投递 |
| AC15 | 视觉一致性 | 求职、招聘工作台与浏览器侧沿用 A 的蓝、黄、绿、橙分工，状态配文字；信息不足是浅底补充提示，已采用、待确认和失败可区分 |
| AC16 | 文档完整性 | 四组共 22 条原始诉求及补充 U01—U07 均对应功能、优先级和验收；首版包含浏览器自动获取、私有匹配池与去投递点击统计，不监控平台进度或自动投递；P0/P1 均为必交、P2 留后续，基础薪资对照在 P0、市场定薪建议在 P2，原始需求记录保持原样 |
| AC17 | 期望填写与来源 | 可保存多条独立岗位期望，每条同时包含岗位方向、多个城市、办公方式、薪资范围和条件强度；分析选择一条并冻结快照，不跨条拼接。未填不等于不限，招聘方按当前候选人记录；不能从现居地、旧薪资或 JD 自动推定期望，默认期望不自动写入 PDF |
| AC18 | 薪资对照 | 同口径期望 20–30K，对岗位 15–25K 提示可能达到、需确认；10–18K 提示低于期望；35–40K 不判为不匹配。面议、缺失、币种／税制不同或换算信息不足均待确认，不擅自用 12 薪、税率、汇率或奖金计算 |
| AC19 | 方向、地点与硬性冲突 | 同名不同职责、近义名称相同职责可解释区别；多城任一接受城市可匹配，远程地域限制需检查。只接受杭州现场、岗位为上海现场时明确地点冲突；硬性冲突不能被高能力分盖过，未知项不能显示全部符合 |
| AC20 | 条件版本与重新分析 | 修改期望不消耗使用次数、不改变旧报告，旧结果显示所用条件及尚未应用新条件的状态；明确确认后重新分析，使用新条件生成新结果，按一次分析计量而不另扣条件对照次数 |
| AC21 | 去投递跳转与计数 | BOSS、猎聘入池岗位的“去投递”可发起前往对应原 JD 的跳转；服务端验证并记录账号、岗位、平台和发起时间，同一次点击重试不重复计数，链接无效或记录失败不计数；今日统计能回溯点击记录，不声称外部页面加载、平台已投递或收到回复 |
| AC22 | 管理端用户、权限、次数、概况和日志 | 有权限的账号可从管理菜单检索用户、查看固定注册身份、在独立页面维护角色权限组合并授予或撤销角色、按该身份适用功能追加次数并查看流水、查看全站概况；可按权限筛选管理操作、登录安全和任务运行日志并打开详情，导出留痕且不暴露业务正文或凭据。普通用户被拒绝，管理员不能改注册身份或自行提权，重复发放不重复入账，权限与次数变更日志含操作者及前后值 |

七天首版能否交付以 P0/P1 全部验收为准；实际作品说明应写清 BOSS、猎聘和面试深度的实测结果，未通过项不得写成已交付。商业验证先确认可用结果、使用行为与成本记录可靠，不以尚未发生的交易证明盈利。
