# Purslyx 需求说明

版本：v0.2 · 更新日期：2026-09-13 · 用途：产品范围、商业规则与首版验收依据。

**Purslyx 面向持续商业化经营，7 天黑客松是第一阶段交付。** 本文描述待实现的产品行为；现有视觉样稿用于确认界面方向，不代表相关功能已经完成。

资料入口：[原始需求记录](需求记录.md) · [当前采用的 A 视觉规范](视觉方案.md) · [赛事信息](../00-overview/黑客松信息.md)。原始记录保留收集时的表述，本文以讨论确认后的双端定位和功能范围为准。

## 1. 产品定位与目标用户

Purslyx 是面向求职者和招聘方的 AI 助手，核心价值是 **有依据的岗位匹配、真实自然的简历表达，以及针对性面试准备**。两端各自导入资料，共用匹配能力，不建立公开人才库、岗位市场或站内投递平台。

| 用户 | 当前问题 | 产品交付的价值 | 付费验证方向 |
| --- | --- | --- | --- |
| 求职者 | 不清楚经历与岗位的关系，也可能遇到岗位方向、地点或薪资不合适；简历表达模板化，制作岗位版本与准备面试耗时 | 同时看清能力与求职条件是否匹配，用真实经历生成可编辑、可导出的岗位版简历，并练习相关面试问题 | 是否愿意为有效的分析、改写和面试练习购买额度 |
| 招聘方 | 简历表达模糊，候选人期望与岗位条件可能错位，核实能力和准备面试耗时 | 对一个岗位、一个候选人给出能力依据、已知期望与岗位条件的对照、待核实事项及面试问题 | 是否愿意为分析质量和节省的评估时间购买额度 |

岗位类型开放，首批重点验证研发、产品、运营，覆盖应届生和有工作经验的求职者。课程项目、校园活动、兼职和正式工作均可成为经历依据；不将缺少实习等同于没有能力。招聘端首版服务单个招聘使用者，不包含企业团队协作与组织权限。

两类客户同时验证付费意愿，商业模式为 **免费试用＋按 AI 功能购买额度**。首版开放注册、限额内测，先记录价值和成本；套餐售价与真实支付在后续验证中确定，不承诺录用结果、真实投递成功率或账号零风险。

## 3. 核心流程与结果要求

### 求职期望与岗位条件（P0）

首次分析前展示求职期望确认步骤。求职者可保存默认期望，每次分析可修改本次使用值；三项均提供填写入口，也允许明确选择“不限／面议”或“暂不填写”。未填写表示未知，不等同不限，不阻止查看已有能力分析，但不能据此声称条件全部匹配。

| 条件 | 求职者／候选人提供的期望 | 岗位侧记录的条件 |
| --- | --- | --- |
| 岗位名称 | 一个或多个期望岗位名称、可接受的岗位方向；明确提供职级时一并保存 | JD 原始岗位名称、实际职责和明确披露的职级，保留来源 |
| 工作地点与方式 | 一个或多个可接受城市，以及现场办公、混合办公、远程工作的接受情况；异地意愿须本人明确 | 实际工作地点、办公方式，以及远程岗位明确披露的地域限制；总部地址不默认等于工作地点 |
| 薪资范围 | 期望下限、上限，币种、月薪／年薪、税前／税后口径；允许选择面议 | 招聘范围、币种、周期、税前／税后口径及已明确的发薪月数，保留原始描述；面议单独标记 |

每项已填写的期望可标记“必须符合”或“可协商”；未选择强度时按“可协商”处理，不能擅自设为硬门槛。默认薪资填写口径为人民币、税前月薪，提交前明确展示；导入资料未写明的币种、周期、税制和发薪月数不得自动补成默认值。倒置或不可读的区间提示修正，修正前不参与数值对照。

用户确认的期望独立于简历经历保存，不自动写入导出的简历。不得从现居地、上一份岗位或当前工资推断未来期望，也不得把 JD 条件反向填成求职者期望。招聘端只记录当前候选人明确提供的信息及来源；缺少时待核实，不套用招聘使用者自己的求职设置。

### 条件如何参与匹配

**结果分为“能力匹配总分＋求职条件对照＋整体建议”。** 能力分回答是否有相关能力和经历；岗位方向、地点与薪资回答双方条件是否适合。条件冲突不改写成能力低分，也不能被高能力分掩盖。整体建议必须同时引用两类结果，不额外虚构一个将未知信息混算的综合百分比。

| 条件 | 对照规则 |
| --- | --- |
| 岗位名称 | 结合名称、职级与实际职责判断方向，不能只按关键词或标题相等判断；名称近义但职责一致可说明对应关系，同名但职责不同仍提示方向差异 |
| 地点与方式 | 在用户明确接受的城市、办公方式范围内对照；多个可接受城市任一符合即可。可接受远程不等于接受任意异地现场办公，远程的地域限制未明确时需确认 |
| 薪资 | 在币种、周期和税前／税后口径一致时比较。招聘上限低于期望下限，提示“披露范围低于期望”；区间跨过期望下限，提示“可能达到，需确认”；招聘下限已达到期望下限，说明这一事实；整体高于期望上限不因无区间交集而判为不匹配。招聘范围不是实际 Offer 承诺 |
| 不可比或缺失 | 一方未提供、面议、口径不同或换算信息不足时标为“待确认／暂不可比较”，不记为零分或默认符合。仅在币种、税制相同且固定发薪月数明确时做月／年换算并展示算式，不估算汇率、税率、奖金或未明确的额外月薪 |

已知条件满足时可结合能力给出建议；标为“可协商”的冲突提示沟通重点；标为“必须符合”的冲突应突出显示，整体结论为“当前不优先，先确认或调整条件”，仍保留能力分析。未知项影响结论的完整性，不能给出“全部符合”。招聘端同样只提示冲突，不自动淘汰候选人。

例如：期望杭州现场办公且必须符合，JD 要求上海现场办公，即使能力分高也提示地点冲突；期望税前人民币月薪 20–30K，岗位为同口径 15–25K，提示部分范围可能达到、需确认实际预算，不能判成完全符合；岗位为 35–40K 时不因高于期望上限判为不匹配。

### 求职者

注册、验证邮箱 → 进入求职工作区 → 设置期望岗位、地点／方式、薪资范围 → 导入简历和 JD → 检查解析内容、岗位条件与本次期望 → 确认额度并分析 → 查看能力依据、条件对照和缺口 → 补充事实 → 确认消耗并生成改写 → 编辑、选择采用 → 调整版式、保存、导出 PDF。可基于同一岗位和简历开启文字面试。

### 招聘方

注册、验证邮箱 → 进入招聘工作区 → 导入一份 JD 与候选人简历 → 检查解析内容与岗位条件，记录候选人已明确提供的期望 → 确认额度并分析 → 查看能力得分、维度、原文依据与条件冲突 → 查看待核实事项与面试问题 → 保存评估参考。候选人的经历缺口列为待核实内容，不由招聘者或 AI 擅自补写为候选人的事实。

### 各环节的输入与输出

| 环节 | 输入 | 必须交付的结果 |
| --- | --- | --- |
| 导入解析 | 粘贴文本或支持的简历文件、JD 文本 | 可阅读、可纠正的内容，以及岗位名称、实际地点／办公方式、薪资披露条件；可回溯到页码、段落或粘贴原文的来源标识 |
| 期望确认 | 期望岗位、地点／方式、薪资范围及条件强度 | 默认期望和本次分析所用条件；保留明确不限、可协商、必须符合与未知的区别，招聘端保留候选人信息来源 |
| 匹配分析 | 用户检查后的简历、JD 及本次求职期望 | 能力总分、固定维度与权重、得分和原文解释；三项条件对照、冲突与未知项；综合两类结果的整体建议与下一步 |
| 事实补充 | 缺口问题与用户的回答 | 单独保存的用户补充记录；可成为新依据，不覆盖原始简历，不自动触发付费功能 |
| 简历改写 | 所选段落、JD、已有事实与用户补充 | 原文与建议对照、改写理由；可修改、采用或保留原文，不擅自加入未提供的数据或成果 |
| 简历导出 | 已确认的岗位版简历与排版设置 | 对应当前版本的 A4 PDF，页数按内容生成，中文正常、无截字或重叠 |
| 招聘面试准备 | 当前 JD 与单人分析 | 与具体岗位要求、简历经历或缺口关联的面试核实问题，留给招聘方判断 |
| 文字面试 | JD、当前简历、用户逐轮回答 | 问题、回答、针对性追问和反馈记录；反馈指出回答依据、遗漏与具体改进方向 |

**匹配解释规则**：两端采用同一套固定且公开的能力维度、权重、条件对照与规则版本，能力总分须能按展示的维度得分与权重复核。每条重要结论关联岗位要求、简历原文、已确认期望或用户补充，不输出无依据的肯定结论。具体能力量表由后续技术设计固化并用研发、产品、运营案例校验；条件对照遵循上文规则。

至少区分“有依据支持”“待确认，当前资料未提供”“存在明确差距”三种结果。未知项不作为“没有能力”的事实结论；信息不足时说明分数的资料边界，不能给出可靠分析时提示补充内容。不得以年龄、性别评分，不自动录用或淘汰候选人，不把匹配分换算为回复、面试或 Offer 概率。

用户编辑或补充经历、修改期望条件不会自动消耗额度，也不会暗中替换已有分析。要求重新分析或生成另一版改写时，先展示对应消耗；历史结果保留所依据的简历、JD 与期望条件版本。修改期望后标记旧报告尚未应用新条件，避免把旧结论当作新内容的分析。

**面试规则**：正常首版按一场 3 个主问题、每题最多一次追问组织。追问承接当前回答；用户可提前结束或中断后继续，报告明确已完成和未回答的部分，不对未回答内容编造反馈。收缩版本仍展示至少 3 个针对性问题，并支持选择一题作答、获得一轮反馈。

**浏览器侧规则**：只在用户主动触发时摘取当前岗位标题、公司、来源链接、工作地点／方式、薪资原文和可取得的职责／要求等内容；未披露或未成功摘取的条件标明待补充，不伪造默认值。带入工作台后由用户检查再保存、分析，摘取本身不消耗 AI 额度。未登录工作台时先引导登录再恢复导入。首版不批量抓取、不辅助填写或提交申请；遇到登录、验证、页面不支持或解析失败时提示本人处理或手动粘贴，不伪报成功。

## 4. 商业化、额度与成本

### 功能计量与免费范围

| 额度类型 | 一次消耗覆盖的范围 | 内测初始额度 |
| --- | --- | --- |
| 分析 | 一份 JD 与一份简历及本次求职期望的完整能力分析、条件对照、缺口和补充问题；招聘端包含面试核实问题 | 20 次 |
| 改写 | 用户确认提交的一次改写请求，可涵盖多个选定段落 | 20 次 |
| 面试 | 一场面试的主问题、约定范围内的追问和结束后的反馈；收缩版本按一场计 | 5 场 |

这三类余额分别记录，求职、招聘工作区共用同一账号的余额，切换角色不重新发放。每个账号完成邮箱验证后领取一次；登录、重复验证或删除资料不重置额度。初始数量可配置，只是内测试用值，不代表已确定的付费套餐或价格。

手动导入和检查、填写事实、设置或修改期望条件、编辑文字、模块排序、保存、查看历史、JD 摘取和 PDF 导出不消耗 AI 额度。条件对照包含在一次分析内，不另计额度。额度用尽仍可处理已有资料。每次有消耗的操作在执行前展示功能、消耗量和该类剩余额度；首版不展示虚假的付款入口或暗中切换到收费。

### 扣减、失败与恢复

| 情况 | 额度行为 | 用户看到的结果 |
| --- | --- | --- |
| 余额足够，发起分析／改写 | 服务端校验并预留对应 1 次额度，成功交付完整且可查看的结果后扣减 | 展示执行状态、结果和更新后的余额 |
| 面试开场 | 预留 1 场，开场问题成功生成后扣减 | 本场后续回答、追问、汇总或恢复不另扣额度 |
| 余额不足或受到频率／并发／全站预算限制 | 不发起新的 AI 调用、不新增扣减 | 说明限制并保留输入，可查看历史、手动编辑或导出 |
| 分析／改写失败，或面试尚未成功开场 | 释放预留额度，不记为成功消耗 | 给出失败原因和可执行的重试入口 |
| 重复点击、响应丢失或网络中断 | 同一执行任务只结算一次；先查询原任务状态 | 已成功则恢复原结果，仍在执行则继续等待，明确失败后可重试 |
| 已开场面试中途失败或退出 | 保留已开始的一场及记录，不再收取开场额度 | 回到原会话继续，已交付的问题与回答可恢复 |

“恢复或重试原任务”和“主动生成新分析／新版本”须区分。后者是新的 AI 功能使用，确认消耗后计次；前者不得因为重复请求产生额外扣减。额度校验、并发控制、预留与结算由服务端完成，不能仅依赖前端按钮状态。

开放注册提供邮箱验证、账号请求频率、并发与全站用量预算控制。限值由运营配置、服务端执行；触达限制时保存草稿，不把限额提示显示为分析成功。

### 成本与商业验证

每次 AI 执行记录所属账号、使用角色、功能、关联任务、模型标识、可取得的输入／输出用量、耗时、成功／失败状态、重试关系和估算成本。估算注明币种和价格依据，缺失字段标为“未知”，不当作零成本；成功、失败及重试调用均计入成本统计。运营汇总只向授权人员开放，不暴露给其他使用者。

| 指标 | 记录口径与用途 |
| --- | --- |
| 首次核心流程完成率 | 分角色观察首次发起分析的账号：求职端完成分析、采用改写并导出 PDF；招聘端获得单人报告并查看依据或面试核实内容 |
| 再次使用 | 首次完成核心流程后 7 天内再次主动发起 AI 功能的账号比例，标明尚未观察满 7 天的样本 |
| 建议采用 | 成功生成改写的请求中，至少一段被用户明确采用的比例；生成结果不等于采用 |
| 面试完成 | 按启用版本统计：P0 完成至少一题回答并获得反馈，P1 完成主问题并得到汇总；以成功开场会话为分母，提前结束单独记录 |
| 额度耗尽后的意愿 | 用户通过明确反馈表示是否希望继续使用、愿意为何种功能付费及原因；不把余额查看或按钮点击等同付费意愿 |
| 每次有效结果成本 | 按角色、功能汇总同一观察期的成功、失败和重试成本，除以成功交付的功能结果数；无成功结果时不计算均值，未知成本单列 |

首版应能按以上口径查询或汇总用量及反馈，不要求建设复杂运营后台。两端分别验证效果与付费意愿，不把免费额度使用率或生成数量直接作为收入证明。后续依据真实反馈和成本验证额度包价格，再实现订单、支付、额度发放与售后；首版不虚构价格、转化率或盈利预测。

## 5. 数据、异常与视觉边界

- **资料分类**：原始简历、岗位版简历、默认求职期望、JD、招聘候选人及其已知期望、分析与面试历史按账号归属，并保留必要的来源关联；分析保存当次期望与岗位条件的版本，支持重新登录后继续查看与处理。
- **删除与隔离**：删除前说明影响的关联资料，确认后不可通过历史入口或原链接继续读取已删除内容。不同账号不能访问彼此的正文、文件、报告或余额；用量台账不保存简历正文，删除资料不重置额度。
- **解析边界**：首版处理文字型 PDF、DOC 和 DOCX；扫描件、图片、加密文件、空白或不可读内容明确提示转换或粘贴文本。失败时不生成空报告、不消耗分析额度。
- **排版边界**：首版是模块流式编辑器，支持顺序和样式调整、A4 自动分页，不做任意坐标画布。长文本或不合适设置须给出可修正的提示，不能静默截断；PDF 与当前已确认版本一致。
- **真实表达**：保留事实、减少空话与模板化措辞，用户可修改后再采用。系统不得把缺口、推测或招聘方的假设写成候选人已完成的经历。
- **错误恢复**：解析、模型调用、登录失效、额度校验和浏览器摘取失败时，说明当前状态并保留可恢复的输入，提供修改、重试、继续登录或手动粘贴入口。
- **视觉规则**：沿用 A：品牌蓝 `#1264E8`、机会黄 `#FFD438`、成功绿 `#39CEA0`、提醒橙 `#FF8A3D`。状态须配文字；信息不足提示使用 `#FFF7F2` 浅底、橙色竖线和深橙色标题 `#964016`，表达补充建议。未采用的改写不提前显示完成，再次编辑后撤回已采用状态。

技术栈、模型和邮件服务、云端存储、评分量表、接口、导出实现、部署与未来支付服务进入后续技术设计；须落实本文的输入输出、公开规则、资料隔离和额度行为，不改变已确认的产品范围。本轮不编写接口定义或为尚未接入的服务指定参数。

## 7. 验收标准

以下是实现后的验收场景，不是当前已通过的测试报告。使用虚构或脱敏的研发、产品、运营 JD，至少包含应届生和有经验者两类资料；同时准备长简历、信息不足、格式错误及两个不同账号的样例。

| 编号 | 场景 | 可观察的通过标准 |
| --- | --- | --- |
| AC01 | 求职者完成核心流程 | 确认岗位、地点与薪资期望，从支持格式导入资料，检查后获得能力分析和条件对照；补充事实并确认消耗生成改写，编辑采用后保存、导出 PDF，原文仍可区分 |
| AC02 | 招聘方单人深入分析 | 一个 JD 和一份候选人简历得到能力评分、条件对照、缺口及面试核实问题；缺少候选人期望时标明未知，不套用招聘者设置；重要结论可追溯，不自动淘汰或录用 |
| AC03 | 评分与事实边界 | 同样简历、JD、期望条件及规则版本在两端使用相同规则，能力总分可按维度复核；缺少描述标为待确认，明确差距有依据；年龄、性别与期望薪资变化不改变能力分，条件变化影响条件对照与整体建议 |
| AC04 | 改写真实性 | 用户未提供的业绩数字、实习和项目不得被补写；补充记录可追溯，手动编辑后不继续显示旧的已采用状态 |
| AC05 | 排版与 PDF 稳定 | 长段落、跨页项目、中文与英文混排、模块换序及字号／间距调整后无文字丢失、重叠或截断；桌面和手机打开 PDF 内容及分页一致 |
| AC06 | 面试保底与增强 | P0 至少 3 个相关问题并完成一题回答反馈；P1 完成 3 主问题、每题最多 1 次相关追问和汇总；提前结束明确未答部分，中断可恢复 |
| AC07 | 浏览器摘取 | BOSS 直聘（P0）与猎聘（P1）验证岗位标题、正文、来源链接及已披露的地点／方式、薪资原文；缺失值明确标记，导入后可检查；未登录或页面不支持时可恢复登录或粘贴，不自动投递 |
| AC08 | 导入与解析失败 | 文本、文字型 PDF、DOC、DOCX 可检查并修正；扫描件、图片、加密或空文件给出明确处理方式，失败不产生空分析报告或扣费 |
| AC09 | 账号、邮箱验证与资料恢复 | 未验证邮箱不发试用额度；验证后仅发一次，重复登录、切换工作区和重复验证不增发；重新登录可恢复自己的资料、版本及面试记录 |
| AC10 | 删除与跨账号隔离 | 两个账号不能读取或修改对方文件、正文、分析、面试、额度；确认删除后不能从旧入口读取已删除内容，删除不重置余额 |
| AC11 | 正常额度消耗 | 默认得到分析 20 次、改写 20 次、面试 5 场；执行前显示对应消耗和余额；两端共用余额，功能成功后只结算对应一次，条件对照不额外计次 |
| AC12 | 失败、重复与并发 | 原任务失败释放预留，成功任务因重复点击或响应丢失只扣一次；恢复面试不再开扣一场；并发预留不超出可用额度，耗尽时不启动新 AI 调用 |
| AC13 | 免费操作与全站限制 | 手动编辑、事实填写、期望设置与修改、查看历史、保存、排序、摘取 JD 与 PDF 导出不消耗 AI 额度；命中频率、并发或预算限制时有提示且输入可恢复 |
| AC14 | 成本与效果记录 | 可分角色、功能复核用量、耗时、失败重试和估算成本；未知不当零；可查询核心流程完成、采用、面试、再次使用及明确意愿反馈，按同一口径计算单位结果成本 |
| AC15 | 视觉一致性 | Web 两工作区与浏览器侧沿用 A 的蓝、黄、绿、橙分工，状态配文字；信息不足是浅底补充提示，已采用、待确认和失败可区分 |
| AC16 | 文档完整性 | 四组共 22 条原始诉求及补充 U01 均对应功能、优先级和验收；P0／P1／P2 及收缩规则无冲突，基础薪资对照在 P0、市场定薪建议在 P2，原始需求记录保持原样 |
| AC17 | 期望填写与来源 | 可保存多个期望岗位、多个城市及办公方式、薪资范围和条件强度；未填不等于不限，招聘方按当前候选人记录；不能从现居地、旧薪资或 JD 自动推定期望，默认期望不自动写入 PDF |
| AC18 | 薪资对照 | 同口径期望 20–30K，对岗位 15–25K 提示可能达到、需确认；10–18K 提示低于期望；35–40K 不判为不匹配。面议、缺失、币种／税制不同或换算信息不足均待确认，不擅自用 12 薪、税率、汇率或奖金计算 |
| AC19 | 方向、地点与硬性冲突 | 同名不同职责、近义名称相同职责可解释区别；多城任一接受城市可匹配，远程地域限制需检查。只接受杭州现场、岗位为上海现场时明确地点冲突；硬性冲突不能被高能力分盖过，未知项不能显示全部符合 |
| AC20 | 条件版本与重新分析 | 修改期望不消耗额度、不改变旧报告，旧结果显示所用条件及尚未应用新条件的状态；明确确认后重新分析，使用新条件生成新结果，按一次分析计量而不另收条件对照额度 |

首版能否交付以 P0 验收为底线；P1 若收缩，应在实际作品说明中明确支持的网站及面试深度。商业验证先确认可用结果、使用行为与成本记录可靠，不以尚未发生的交易证明盈利。
